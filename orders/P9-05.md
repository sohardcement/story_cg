# 工单 P9-05：分镜规则（每镜单主角、先建立道具归属）+ 回归重跑

先读 AGENTS.md（含补充禁令）、PROGRESS.md 决策 D12–D16、`reports/P9-02.md`、`reports/P9-04.md`（审核器 v2 与新的 reliability 配置）。在现有代码上修改，全部走正式入口。

## 要做的事

1. **每镜强制单主角**（D16）：分镜 schema 与校验器要求每镜只描述主角的**一个**姿态/动作瞬间；同一镜里出现"睡着…站着…""先…再…"这类两个姿态的描述，或要求主角在同一画面出现两次（倒影除外，需显式声明 `reflection`），校验器拒绝并给出字段级反馈。拼装提示词时也不得把两个姿态的 tag 放进同一镜。通用规则，不写具体动作词表特例；可以用结构化字段（每镜一个 `pose`/`action`，以及 `reflection` 布尔）来实现。
2. **先建立道具归属**（D16）：当剧情涉及同类道具的归属/交换/拿错（登记的同类道具有不同 owner 或剧情要求区分），分镜必须在这些道具第一次形成对比**之前**，用至少一个镜头清楚交代"哪件属于主角"（例如主角拿着/放下自己的那件，可区分特征清楚可见），校验器检查 props 的 owner 字段与首次出现顺序。通用规则。
3. 离线测试覆盖以上两条（两姿态拒绝、倒影声明放行、归属先于对比、无归属剧情不受影响）。
4. **回归重跑**（正式默认入口，串行；每组 ≤40 张、≤60 分钟）：
   - `月城柳` / `月城柳在办公室整理文件时睡着了，醒来发现天已经黑了。`（上次第 1 镜两个主角）
   - `芙莉莲` / `下雨后在车站发现自己拿错了伞。`（上次读不出"拿错"）
   - `约尔` / `约尔第一次学做蛋糕，结果烤焦了，最后还是笑着切了一块。`（上次被"发髻看不见判成缺失"降为 L4；审核器 v2 后应能重新判定层级）
   每组完成后拼图复制为 `review/<角色>-<剧情简称>-v2.jpg`，与旧版并排拼成 `review/P9-05-<角色>-前后.jpg`。
5. `reports/P9-05.md`：逐组逐镜看图判断、新审核项（单主角计数、瞳色采样）结果、盲审是否读出关键事件和结局、层级判定变化、用量与是否超限、已知问题。
