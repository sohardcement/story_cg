# 工单 P3-01：定妆图 + 身份参考机制试点（IPAdapter vs Qwen Image Edit）

你是执行者，先读 AGENTS.md（含末尾「监工补充禁令」），再读 TASK.md §3 的 P3、§4、§6 第一条，以及此前所有 reports。在现有代码上继续，画风参数从 `config/style.json` 读取。

## 目标

1. 实现"定妆"步骤：身份（identity）+ 默认服装（outfit）+ 画风（style.json）→ 定妆图，定妆图必须先通过审核，才能生成整组（TASK.md §6 第一条）。
2. 让定妆图**真正参与**后续每镜的生成（不是只在审核时看）。用两种机制各做一次小试点，给监工看图决定用哪个。

## 已核实可用的节点与模型（P0，见 PROGRESS.md）

- IPAdapter（SDXL）：`IPAdapterModelLoader` → `ip-adapter-plus-face_sdxl_vit-h.safetensors`；`CLIPVisionLoader` → `CLIP-ViT-H-14-laion2B-s32B-b79K.safetensors`；`IPAdapterAdvanced` 等。没有非 face 版的 SDXL plus 模型。
- Qwen Image Edit 2511：`UnetLoaderGGUF` → `qwen-image-edit-2511-Q4_K_M.gguf`；`CLIPLoader`(type `qwen_image`) → `qwen_2.5_vl_7b_fp8_scaled.safetensors`（或 GGUF 版 `Qwen2.5-VL-7B-Instruct-Q4_K_M.gguf`）；`VAELoader` → `qwen_image_vae.safetensors`；`TextEncodeQwenImageEditPlus`；可选 Lightning LoRA `Qwen-Image-Edit-2511-Lightning-4steps-V1.0-bf16.safetensors`。
- 局部重绘：`SetLatentNoiseMask`、`InpaintModelConditioning`、Fooocus inpaint。
- 参数以 `verify/object_info.json` 和实时 `/object_info` 为准，节点输入名不要凭记忆写。
- 禁止安装节点或下载模型（TASK.md §2 选项 A）。

## 要做的事

1. **定妆图**：
   - 构图固定为通用的角色设定图风格：单人、正面或微侧、全身或膝上、站姿自然、纯色/简单背景、服装完整可见、表情平静。这些是通用规则，写在配置里。
   - 生成后跑审核（身份清单对照 identity.json 的来源 tag；单张的人体/手部）。未通过按诊断重试，最多 3 次；三次都不过就停止并报告，不要继续生成整组。
   - 定妆图及其面部裁切保存在任务目录，manifest 记录参考关系（哪张图用了哪个参考、以什么方式、什么强度）。
   - 定妆图可以在同一角色的多个任务之间复用（按 identity 内容哈希缓存），复用时 manifest 注明来源任务。
2. **机制 M1：IPAdapter**。WAI 出图时用定妆图面部裁切（或定妆图）作参考注入。先用两档强度（例如 0.4 / 0.7，自行查证合理范围后决定），每档出 2 镜。
3. **机制 M2：Qwen Image Edit → WAI 重绘**。以定妆图为输入图，用分镜描述让 Qwen Image Edit 生成该镜构图（保持人物与服装），再用 WAI + 画风 LoRA 以中等 denoise 做 img2img 统一画风。同样 2 镜。denoise 取值自行试 1 档并说明理由。
4. 两个试点都用同一角色、同一分镜的两镜（从 P1-04 的分镜里选一个近景、一个全身带道具的镜头），以及同样的 seed。另外把"无参考"的同两镜也出一次作为基线（如 P1-04 已有同分镜同 seed 的图可直接引用，注明路径）。
5. 拼一张对照图 `review/P3-01-pilot.jpg`：行 = 基线 / M1-低 / M1-高 / M2，列 = 两镜 + 最左一列放定妆图。每格标注。
6. 对每格跑一次跨图一致性审核（参考=定妆图），把结果汇总成表写入报告。你自己看图的判断也写上，并说明两者不一致之处。
7. 写清两种机制各自的代价（每镜耗时、显存/失败情况、对画风和构图的影响）。
