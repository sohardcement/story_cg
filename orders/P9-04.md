# 工单 P9-04：审核器 v2（区分看不见与不存在）→ 冻结 → 用监工确认的 v1 + v2 样本重新校准

## 第一步：审核器改版（只针对 D14，以及把 P9-02 的检测类项纳入可靠性体系）

1. **看不见 vs 不存在**（D14）：视觉模型审核身份/服装逐项时，先判断"该特征按此角度/取景/遮挡**理应可见吗**"：理应可见却没有 → `fail`（absent）；因角度、遮挡、出画、太小而看不到 → `not_visible`，并写明原因类别（angle / occluded / out_of_frame / too_small）。不得用"没看到"推断"不存在"。层级判定（L2 知识探针、L3 定妆比对）同样适用：`not_visible` 不否决。
2. 检测类审核项（P9-02 新增的 `eye_color_sampled`、`protagonist_count`、配饰粗检）进入与视觉项相同的结论归并与可靠性标注体系。
3. 修改后跑离线测试，然后**冻结 v2**：把 `src/storycg/review.py` 及审核提示词、检测类审核项代码与阈值配置的 sha256 写入 `calibration/v2/reviewer_freeze.json`。冻结后本工单内不再改。

## 第二步：校准

1. 样本：`verify/P4-labels.json` 中 confirmed 的 v1 样本（检查 v2 是否让原来可靠的项退化）+ `verify/P9-labels.json` 中 confirmed 的 v2 样本。逐项真值以这两个文件为准，`ambiguous` 不计。
2. 每个样本跑 2 次（视觉项）；检测类项是确定性的，跑 1 次并验证重复运行结果一致。
3. 统计：每项检出率（只算 fail）、误报率、"真值 not_visible 却判 fail"的比例（D14 要消除的错误，单独列）、两次不一致率；与 v1（P4-02）结果并排对比。
4. 可靠性规则不变（检出 ≥75%、误报 ≤20%、error/ok 样本各 ≥3），写 `config/review_reliability.json` 的 v2 版（保留 v1 文件副本），运行时标注同前。
