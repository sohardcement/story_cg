## 要做

### A. compile 的 needs_user 输出和 make / status 同形（第 3 条）

现状（`src/storycg/agent.py` `main()` 的 compile 分支）：
- 身份没锁定（歧义名，如 `--character 御坂`）：打印 `{"status": "identity_not_locked", "identity": {...}}`，退出 2。没有顶层 `needs_user`、`question`、`options`。
- 清单外角色（如 `--character himegami_aisa`）：打印 `{"status": "needs_user", "reason": ..., "question": ...}`，退出 2。没有 `needs_user` 布尔和 `options`。
- compile 不接受 `--tag`、`--work`（argparse 报 unrecognized arguments）。

改成：
- 两种情况都输出顶层 `needs_user: true`、`reason`、`question`、`options`。这几个键和 `make` 停在 needs_user 时 `status` 输出的**同一来源**：make 走到 needs_user 时 agent.json 里的 reason / question / options 是 `storycg/identity.py` 的 `needs_user(...)` 一带生成的，compile 调同一条路，不另写文案。歧义名的 `reason` 就是 make 给的 `identity_ambiguous`，`options` 是候选列表（元素结构和 status 的 options 一致）；清单外的 `reason` 是 `character_not_in_wai_list`，`options` 为 `[]`。
- `status` 键保留，值统一为 `"needs_user"`；原来的 `identity` 对象保留在 `identity` 键下。退出码仍 2。
- compile 加 `--tag`、`--work`，语义同 make（走 make 用的同一个身份解析入口，传了就按它锁定）。

### B. stdout 永远 JSON（第 4 条）

现状：`src/storycg/__main__.py` 兜底的 `except (OSError, ValueError, KeyError)` 只往 stderr 打一行 `storycg: ...`，stdout 为空，退出 1。能走到这里的至少有：`--beats` 文件不存在（OSError）、`--shots 3`（"story jobs require 4 to 6 shots"）、`--profile bogus`（"unknown profile ..."）。

改成：兜底处同时往 stdout 打一行 `{"status": "error", "kind": "<异常类名>", "message": "<str(exc)>"}`（`agent.py` 里 verify-llm / write-beats 已用这个形状），stderr 那行保留，退出码仍 1。不改 argparse 自己的错误（缺参数、未知参数仍是 stderr + 退出 2）。

### C. 任务命令对错误路径的文案（第 5 条）

现状：
- `status /tmp/x` → stderr 和 JSON 的 `error` 都是 `ValueError: agent job paths must be inside the project workspace` 原文，退出 1。
- `status <工作区内不存在的目录>` → `ValueError: story job not found`，退出 1。
- `status compile/cmp-xxxx`（compile 留下的草稿目录，里面有 job.json）→ 返回一份 `phase: unknown` 的完整 status，退出 0。

改成：三种都输出 `{"status": "error", "kind": "not_a_job", "message": <中文>}`，退出 1。文案：工作区外 → "路径不在项目工作区内，不是任务目录"；不存在 → "任务目录不存在：<路径>"；compile 草稿目录（路径在 `compile/` 下）→ "这是 compile 的草稿目录，不是任务目录；任务目录在 jobs/ 下"。判断放在 job_dir 解析那一处，status / pick / approve / resume / cancel / deliver / reshoot / resolve 共用。

### D. beats-guide 的镜数边界（第 9 条）

现状：`beats-guide --shots 2` 和 `--shots 7` 正常输出，并新建一个 `drafts/cg-*/` 空目录；compile / make 拒绝 4–6 之外。

改成：beats-guide 和它们用同一个校验（把现在抛 "story jobs require 4 to 6 shots" 的判断抽成一个函数，三边调用），校验在新建 drafts 目录之前，失败走 B 的 JSON error，退出 1，不留目录。
