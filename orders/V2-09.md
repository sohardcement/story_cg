# 工单 V2-09：场景物件过滤把天气、光线词误当成物件

监工跑 v2 对比集时发现，V2-06s 的场景物件上限把天气和光线 tag 当成了物件计数，剧情关键信息因此被丢掉：

- 第 2 组 `.v2/jobs/cg-e0d8af8324b6`：第 3 镜是近景，剧情点是"发现只是下雨"。场景 tag `office, day, rain, window` 里的 `rain` 被丢，画面没有雨。
- 第 1 组 `.v2/jobs/cg-5f62911b4a65`：中景的 `overcast`、`wet_ground`、`dim_lighting` 被丢；`rain` 占了一个物件名额。

原因是 `config/default.json` 的 `scene_rules.non_object_tags` 是一份手写的起步清单，缺 `rain`、`overcast`、`dim_lighting` 等常见词。V2-06s 报告的已知问题 2 提过这一点。

开工前先读 `.v2/reports/V2-06s.md`。工作目录、写入范围、git 规则按 AGENTS.md 第 8、9 条执行。

## 要做

1. **非物件 tag 的依据改用 Danbooru tag group**，做法和 V2-08 的 eyes 组一样：存快照，配置里写来源 URL 和 sha256。
   - 先用 Danbooru wiki API 查出哪些 tag group 覆盖天气、天空和时间、光线、地点和背景，选用并在报告里列出来。
   - 判定规则："是否非物件" = 在这些组里，或者在现有手写清单里。现有清单保留，作为补充。
   - 不属于任何一组、也不在清单里的 tag，仍按物件计数。
   - `window` 这类实体物件仍按物件计（CAP-04 的依据不变）。
2. **被丢弃的场景 tag 要留记录**：`assemble_prompt` 返回的 `dropped_scene_tags` 现在没有存下来。改为写进该次 attempt 的记录；如果某镜丢了 tag，交付说明（result.md 的已知问题）里加一行"第 N 镜因景别物件上限省略了：…"。
3. 不改物件上限的数值（近景 0、中景 2、全景/远景 3），不改会引出别的动作的物件清单。

## 验证

- 单元测试：`rain`、`overcast`、`dim_lighting`、`night`、`cloudy`、`lightning`、`moonlight` 不计物件；`window`、`cat`、`desk` 计物件；attempt 记录和 result.md 两处都要有被丢 tag 的记录。
- 全量测试通过。
- 离线回放：对 `.v2/jobs/cg-5f62911b4a65`、`.v2/jobs/cg-e0d8af8324b6`（只读）的 storyboard，以及 V2-08 r1 回放里 12 份通过的 storyboard，逐镜列出修改前后被丢的 tag。
