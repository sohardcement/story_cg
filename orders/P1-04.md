## 背景（监工看 P1-02 拼图的结论）

`review/芙莉莲-下雨后在车站发现自己拿错了伞.jpg`：身份和服装稳定，但只看图完全读不出剧情。
1. 4 镜几乎都是居中站立全身，"medium shot" 实际出了全身——景别和机位没有生效。

4. 镜头块是英文散句（含 `protagonist` 等对 WAI 无意义的词），WAI/Illustrious 主要吃 danbooru tag。

## 要做的事

1. **镜头块 tag 化**：分镜 schema 中每镜增加由运行时 LLM 给出的 danbooru 风格 tag（动作、表情、手部与道具关系、姿态等），脚本校验：
   - tag 必须是真实存在的 Danbooru tag（用 `/tags.json` 查询并缓存；不存在的丢弃或要求重写，记录处理结果）。
   - 仍然拒绝外貌类 tag（发色、瞳色、发型、体型等），通用规则，不写角色特例。
   - 保留一句英文/中文的镜头说明供分镜展示与审核使用，但它**不进入**正向提示词。
   - 提示词里的 tag 统一用空格形式（`long hair` 而不是 `long_hair`），身份块仍逐字来自 identity.json（只做确定性的下划线→空格转换）。
2. **景别与机位映射**：在配置里把景别映射到 danbooru 构图 tag（例如 wide → `wide shot, full body, scenery`；full → `full body`；medium → `cowboy shot`；closeup → `upper body` / `portrait` / `close-up`），机位映射到 `from above` / `from below` / `from side` / `from behind` / `dutch angle` 等。映射写在配置文件里，不写死在代码里。
3. **关键道具登记**：分镜 schema 增加 props 状态（与 identity/outfit/scene 同级）：每个关键道具有 id、可区分的视觉描述 tag（颜色、图案等）。剧情里需要区分的同类道具（如两把伞）必须有明显不同的颜色或图案，脚本校验同类道具的描述不能相同。每镜引用道具 id，拼装时逐字插入该道具的描述，并写明在谁手里、在哪里。
4. **场景状态负面词**：scene 状态增加该场景必须排除的元素（例如"雨后"应排除正在下的雨 `rain`），拼装进负面提示词。由 LLM 在分镜中给出、脚本校验为真实 tag。
5. **构图多样性校验**：相邻镜头的景别和机位不能完全相同（除非分镜说明了理由），第一镜应为交代环境的镜头。违反时要求 LLM 重写（计入调用上限）。
6. **重跑对照**：用同一输入（`芙莉莲`，`下雨后在车站发现自己拿错了伞。`，4 镜）新建任务重跑，生成拼图 `review/芙莉莲-拿错伞-P1-04.jpg`，并与 P1-02 的拼图并排拼成 `review/P1-02-vs-P1-04.jpg`（左旧右新，标注清楚）。
7. 自评：按 TASK.md §7 第 3 层，只看新拼图你能读出什么故事，如实写。若审核器（P1-03）已可用，对新任务跑一次 `review` 并附结论。
