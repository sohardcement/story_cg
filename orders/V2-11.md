# 工单 V2-11：编译阶段的确定性改写

在 V2-10 的 `compile_beats` 基础上加确定性改写：能由代码改的直接改，不再打回给 agent。依据是 `TASK-v2.md` §9 第 2、4、5、6 条。工作目录、写入范围、git 规则同 V2-10（AGENTS.md 第 8、9、10 条）。先读 `reports/V2-10.md`。

## 要做

每条改写都记进编译日志（`plan_log.json`），格式是"第 N 镜：原值 → 新值，原因"；同时在分镜的 `story_note` 里追加一句中文说明。改写在词汇表校验之前完成，校验只针对改写后的结果。

1. **表外动作改用稳定组合**：
   - 某镜的（景别、角度、pose）在词汇表里查不到（表外），而同一个 pose 在本层级有稳定档的条目时，把景别和角度改成那个条目的。
   - 有多个候选时，优先景别相同的，其次角度相同的，再其次 id 小的。
   - 第 1 镜只能在 wide 景别的候选里选，首镜必须是远景的规则不能被改写破坏。
   - expression 不改。
2. **不可用组合自动替代**：命中"不可用"条目，且登记的替代有 `substitute_id` 时，改成替代条目的景别、角度和 pose。替代只有改写文字、没有 id 时，仍然报错，把那段改写文字原样放进错误信息里。
3. **"有时"超额时再收一轮**：第 1、2 条做完后，"有时"（包括表外）仍多于 1 镜时：
   - 对除第 1 镜外命中"有时"条目、且同一 pose 有稳定条目的镜头，按第 1 条的选法改成稳定组合，从后往前改，直到不超额；
   - 还超额就报错，列出是哪几镜。
4. **近景放开声明道具**：`prompt_rules.filter_scene_tags` 里，近景对"本镜声明的那一个道具"（`prop_tags`）放行，其余物件的上限仍是 0 件。中景和远景的规则不变。
5. **室内的天气补窗户**：
   - 判断场景是室内的依据：场景 tag 含 `indoors`，或者地点 tag 属于 Danbooru `tag_group:locations` 快照的室内部分（用 V2-09 已有的快照，不要另写清单；如果快照分不出室内和室外，在报告里说明你怎么做的）。
   - 室内场景出现降水类 tag（rain、snow、raindrops、thunderstorm 等，写进配置，附来源）时，补上 `window`。
   - 这个 `window` 不占物件名额，近景里也保留。
6. **服装状态和 tag 一致**：某镜的 `clothing_state` 和上一镜不同，但服装 tag 集合（canonical 后比较）完全相同时，报错："第 N 镜的服装状态变成了 X，但服装 tag 没变，请写出 X 对应的服装 tag"。

## 验证

- 每条改写都要有单元测试，包括边界：
  - 第 1 镜只在 wide 里选；
  - 没有稳定候选的表外动作不改写，计为"有时"；
  - 有替代 id 的自动替代，只有改写文字的报错；
  - 超额时的收敛顺序；
  - 近景只放行声明道具，其他物件照样丢；
  - 室内补窗户，室外不补；
  - 服装状态变了而 tag 没变时报错，状态和 tag 一起变时通过。
- 全量测试通过。
- **离线回放**：把下面这些分镜模型原始输出（只读，取各自 `plan_log.json` 里每次调用的 `raw`）当成 beats，逐次跑编译，列出"V2-10 编译结果"和"V2-11 编译结果"的对照，以及每一条改写：

  - `.v2/jobs/cg-b9352a5f6f2a`：第 1 组首跑，5 次全被拒；
  - `.v2/jobs/cg-9c94a5857243`；
  - `.v2/jobs/cg-b42fae34baa4`。
