# 工单 V3-02：cancel 成功按成功报、resume 清掉旧 error、cancel 不吃掉 `--more`（TASK-v3 §3.1 第 1、2 条）

起因同 V3-01。实测（`jobs/cg-ed4224ca2074`，2026-10-19）：出图中 `cancel` 生效后退出码 1，`error` 是 "worker 收到信号 SIGTERM 后退出；可以运行 resume 接着跑"，紧接着 `resume` 的输出也带这条；SKILL.md 要求"有 error 时原样说明"，调用方会把一次正常取消讲成故障。另外 `pick --shot 2 --more` 之后出图中 cancel 再 resume，这批不再出，`pending_pick` 仍 3 张，没有任何提示（`candidates.json` 里该镜 `more: 1, more_done: 1`）。

工作目录、守则、命令同 V3-01（`.v3`，`PYTHONPATH=$PWD/src`，basetemp `.pytest-tmp/V3-02`）。在 V3-01 验收后做，开工先跑全量记基线。

## 现状（代码位置）

- `src/storycg/agent.py` `install_exit_record()`：收到 SIGTERM / SIGINT 时，`cancel_requested` 为真写 phase `cancelled`，否则 `stopped`；两种都把 `error` 写成那句话，然后 `os._exit(1)`。
- `main()` 的 cancel 分支：`cancel_job()` 发信号后读 status 输出；main 末尾按 `error` 非空给退出码 1（找到那处确认）。resume 分支启动 worker 前不清 `error`。
- `src/storycg/candidates.py` `run_candidate_delivery()` 的 `while human_review(config) and slot['more'] > slot['more_done']` 循环：`more_done += 1` 和落盘在 `_run_round(...)` **之前**；被信号打断时 more_done 已经加了，resume 后条件不成立，这批不出。打断时 state.json 里已提交完成的那张（孤儿）会被下一次 `--more` 的 `_run_round` 接着用（当天 a004 就是这样被第二次 `--more` 用上的）。

## 要做

1. 信号退出：`cancel_requested` 的 SIGTERM → phase `cancelled`、`error` 为 None、新字段 `stopped_by: "cancel"`；其它信号 → phase `stopped`、`stopped_by: "signal"`，`error` 保留现有文案。`status` 输出加 `stopped_by`（没有就 null）。
2. `cancel` 命令成功时退出 0（error 为空后应自然满足；确认 main 末尾那条规则，不要为 cancel 加特例）。cancel 失败（没有在跑的 worker）照旧 error + 退出 1，文案改中文："没有在运行的 worker，无需取消"。
3. `resume`：启动 worker 前 `update(root, error=None, stopped_by=None)`；resume 的输出不带旧 error。
4. `--more` 不丢：把 `more_done += 1` 和落盘移到 `_run_round` 返回之后。先确认 `_run_round` 对 state.json 里已完成的同编号候选是跳过不重出的（看它怎么处理已有 attempt / recovering），把确认结果写进报告。效果：打断后 resume，这批接着出完，候选数 = 3 + 每轮张数；打断时留下的孤儿图被接上，不多提交。
5. 不改 SKILL.md（V3-07 做）。
