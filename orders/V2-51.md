## 要做

### A. 改写保留动作 tag

1. `shot_contract.py` 新增一个函数，按 `materialize` 现在的规则算 `shot.tags`：`[pose, action_tag, expression]`，去掉空值，保持顺序去重。`materialize` 改用它，输出逐字节不变。
2. `beats._set_combo` 也用它，带上这一镜的 `action_tag`。三条改写规则（`off_table_stable`、`unusable_substitute`、`sometimes_overflow`）都走 `_set_combo`，都要覆盖到。
3. 规则 2 会换 pose。换完后 `action_tag` 和新 pose 相同时，交给 `_collect_errors` 现有的"动作 tag 和 pose 相同"检查报错，不在改写里特殊处理。

### B. 身份解析时去掉 Danbooru 上废弃或不存在的 tag

1. `identity.py` 新增一个函数，在 `resolve_identity` 里 `enrich_identity` 之后、算 `identity_block` 和 `outfit_block` 之前调用：
   - 查询对象：`result['appearance_tags']` 和 `result['default_outfit_tags']` 里所有 tag 去重后排序，用 `source.get('/tags.json', {'search[name_comma]': '逗号连接的名字', 'limit': 本批个数})` 查，每批最多 100 个。名字里含逗号的单独用 `search[name]` 查。两个列表都为空时不发请求。
   - 判定和 `TagRegistry.lookup` 完全一样：响应里有 `name` 完全相等、且 `is_deprecated` 不为真的条目，才算可用。
   - 不可用的 tag 从两个列表里删掉，记进 `result['unavailable_identity_tags']`，每条为 `{'tag', 'field'（appearance_tags 或 default_outfit_tags）, 'reason'（deprecated 或 not_found）, 'source'（请求 URL）}`。
   - 请求失败照常抛出，和其他 Danbooru 请求一样由入口转成 `needs_user`，不吞掉。
   - 只查这两个列表。`alternate_outfits`、`outfit_candidates`、`appearance_candidates` 不动。
2. `beats.character_guide` 多返回 `unavailable_tags`（tag 名列表）；`beats-guide` 在"标准服装 tag"一行后面，列表不为空时加一行：`已去掉 Danbooru 上废弃或不存在的 tag：a, b`。为空时输出和现在一字不差。
3. 已有任务的 `identity.json` 不重算，`resolve_job` 照旧复用已存的身份。

### C. 编译删掉或替换的 tag 写进改写记录

1. `compile_beats` 在 `validate_tag_lists` 之后，取这次编译的 tag 查询记录里 `action` 为 `discarded`、`pose_replaced`、`pose_omitted` 的条目，变成改写记录，追加进 `record['rewrites']`，并按 `rewrite_board` 的做法把文字追加到 `story_note`。
   - 只处理 `field` 以镜号开头的条目（形如 `2.outfit.tags`）。镜号是第一段，字段是其余部分。
   - 同一种动作、同一个字段、同一个 tag（替换时还要同一个替换值）合成一条，镜号按顺序用顿号连接。
   - 文字格式（照抄，`{镜号}` 为 `1` 或 `1、2、3`）：
     - discarded：`第 {镜号} 镜：{字段} 的 {tag} → 删除，Danbooru 上不存在或已废弃`
     - pose_replaced：`第 {镜号} 镜：shot.pose 的 {tag} → {替换值}，Danbooru 上不存在，换成同词的体位 tag`
     - pose_omitted：`第 {镜号} 镜：shot.pose 的 {tag} → 不进提示词，Danbooru 上不存在，也没有可替换的体位 tag`
   - 每条改写记录的键和 `rewrite_board` 的一样（`shot` 取第一个镜号，另加 `shots` 列表），`rule` 分别为 `tag_unavailable`、`pose_replaced`、`pose_omitted`。
2. `compile` 命令 valid 时的输出多一个键 `rewrites`：这次编译全部改写记录的文字列表，包括 `rewrite_board` 的。其余键不变。
3. 确认页的 `compile_rewrites`（`display.compile_rewrites`）读的就是 plan_log 里最后一次 valid 编译的 `rewrites`，不用改，确认这些新条目能出现在里面。
4. 不改 `_collect_errors` 和 `validate_tag_lists` 的判定，也不把删 tag 改成报错。
