# 工单 V2-22：并排挑选的离线小实验（不改正式代码）

## 背景

V2-21 的上线冒烟（`.v2/jobs/cg-8092d80fd20b`）暴露了一个问题：4 镜里有 3 镜，3 张候选都没有任何可靠项失败，挑选只能按候选序号定胜负。原因是审核器的"表情"项校准为不可靠，单图审核分不出哪张更能表现这一镜的动作和表情。

用户同意先离线试一种做法：把一镜通过筛选的候选并排放在一张图里交给视觉模型，问它哪张最能表现这一镜的动作和表情。每镜多 1 次调用。

真值由监工在调用模型之前冻结，放在 `verify/` 里。**你不得读取 `verify/v2/pick_labels.json`，也不得读取 `verify/` 下任何关于这次实验的文件。** 结果由监工打分。

工作目录、写入范围、git 规则同 V2-20。命令带 `PYTHONPATH=$PWD/src`。

## 要做

1. 写 `tools/v2_22_pick.py`，只读 `.v2/jobs/cg-8092d80fd20b`：
   - 从 `candidates.json` 取每镜通过筛选的候选（`screen` 为空的）。只处理通过筛选的候选有 2 张及以上的镜，也就是第 2、3、4 镜。
   - 拼图：把这几张候选横向排成一张图，保持原图比例，每张下面标 A、B、C。拼图存到 `reports/assets/V2-22/`。
   - 提示词：只给这一镜自己的要求，取自 `storyboard.json` 这一镜的 `shot` 字段，包括动作或空间关系、表情、景别。不给整组剧情，也不给其他镜。问模型：哪一张最能让人一眼看出这一镜要求的动作和表情？要求输出 JSON：
     - `best`（字母）；
     - `reason`；
     - 每张一条 `{action_visible, expression_visible}`，取值为 yes / partly / no。
   - 用现有的视觉模型服务（`config/default.json` 的 `model_service_url`）和项目里现有的视觉调用客户端，JSON schema 约束沿用项目已有的写法。
2. **顺序偏差检查**：每镜跑两次，一次按候选序号正序排，一次倒序排。两次的字母要换算回候选序号。
3. 共 6 次调用，上限 8 次（留 2 次给失败重试）。每次的请求、拼图路径、原始回复和换算后的候选序号，都存到 `reports/assets/V2-22/calls.jsonl`。
4. 不改 `src/`、`config/` 和 `tests/`。

## 验证

- 报告里给出可直接运行的命令。
- 一张表：镜号、候选池、正序选了哪张、倒序选了哪张、两次是否一致、模型给的理由（简短）。
