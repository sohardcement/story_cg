# 工单 P10-04：服装细节不一致接入修复循环；动作 tag 解析不能退化成意思不对的词

先读 AGENTS.md（含补充禁令）、PROGRESS.md 的 D23、D24、D25 和"Hermes 实测 T4"一节，以及任务 `jobs/cg-129ca5876d7b/`（只读：cycle.json、review.json、plan_log.json、storyboard.json）。

## 背景（监工在 Hermes 实测 T4 中发现）

1. **服装细节判了不一致，却不触发修复。** P10-02 的 `outfit_detail_vs_portrait` 已校准为可靠。T4 中它把第 1、3、4 镜判为 mismatch（外套长度、颜色和定妆不一致，监工看图确认判得对），但 `cycle.json` 的 `problem_methods` 里没有这一项，修复循环什么都没做。服装在 v1 的保证范围内（D23）。
2. **动作 tag 解析退化。** 第 3 镜剧情是"脸红害羞地捂住脸"。规划把 spatial_relation 写成了"hands covering face"，pose 却给了不存在的 `hands_on_head`。tag 解析拿到的候选是 head_on_chest、sitting_on_head、legs_over_head、own_hands_together、arm_behind_head，最后选了 `arm_behind_head`，于是画成了手放脑后。动作同样在 v1 范围内。

## 要做的

1. **接入修复**：所有已发布为 reliable 的审核项，判 fail 时都要能映射到修复方法。`outfit_detail_vs_portrait` 用和 `outfit` 相同的方法（instruction_edit → relayout）。用通用方式实现，比如通过 reliability_key 或映射表，并补一条测试：今后新增的 reliable 项如果没有修复方法映射，测试就失败。unreliable 或 unverified 的项维持现状，不否决、不修复。
2. **动作 tag 解析**：pose 或动作 tag 在 Danbooru 上找不到精确词时，不能退而选一个和该镜描述（action、spatial_relation、change_from_previous）对不上的候选。做法自定，要通用、可测试。比如候选必须和描述共享关键身体部位与动作词；或者先用描述里的短语去查 Danbooru 已有的 tag；都对不上就不加 pose tag，并在 plan_log 里记录。不得写入针对某个剧情或角色的特例。
3. **离线测试**：先红后绿。覆盖 T4 的两种情况，fixture 要用通用的虚构数据，不要复制剧情原文。
4. **在线回归**（1 组）：用 CLI（不经过 Hermes）对同一个角色和剧情重跑一组：`--character 'fern_(sousou_no_frieren)' --story '菲伦第一次被人夸奖，先是愣住，接着脸红害羞地捂住脸，最后偷偷笑了' --shots 4`，默认模式。要求：
   - 判了服装细节 mismatch 的镜头，修复循环确实执行了修复（cycle.json 里能看到诊断→假设→改动→结果）。
   - 捂脸那一镜的 pose 或动作 tag 的意思和"捂脸"一致，或者按规则不加 pose tag。
   - 输出前后对照拼图 `review/P10-04-菲伦-前后.jpg`（左边是 T4 原拼图，右边是本次结果）。
