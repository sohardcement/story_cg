# 工单 V2-25：接入 WAI 角色清单：中文名查角色、清单内角色直接判 L2

先读 `/work/workspace/manga_skill/TASK-v2.md` §10.4，以及 `PROGRESS.md` 里的 D67、D68，那里写了留出集暴露的问题。

工作目录、写入范围、git 规则同前，见 `.v2/AGENTS.md` 第 4、8、9、10 条。命令带 `PYTHONPATH=$PWD/src`。

## 背景（监工已查）

留出集暴露了三个问题：

1. **"2B"解析有歧义。** Danbooru autocomplete 的结果是 `2b_(nier:automata)` 和 `otoja_(2bro.)` 两个候选，流程停下来问人。"寄叶二号B型"等写法也一样。
2. **2B 被误判成 L3。** 底模其实完全认得 2B。但层级探针图里，她的眼罩挡住了眼睛，瞳色比对 2 次 not_visible、1 次 fail，结果按失败处理，被判成 L3。
3. **雷姆被判成 L4，流程停下来问用户。** 底模也完全认得雷姆。问题出在她的 wiki：里面有一句讲双胞胎姐姐拉姆，带进了 pink_hair、red_eyes，和蓝发、蓝眼冲突。冲突的结果是两项都不锁定，可靠项就没有了，层级判定无从比对。（这个 wiki 冲突的规则问题本单不修，另开一单。）

用户同意接入第三方数据 `mirabarukaso/character_select_stand_alone_app`（MIT 许可证）里的 WAI 角色清单 `data/waiIllustriousSDXL_v160_characters.csv`：
- 它列的是 WAI Illustrious v16 只靠 tag 就能画出来的角色，共 5093 个；
- 每行格式是 `中文名（作品名）,英文 tag`，例如 `雷姆（Re:从零开始的异世界生活）,rem (re zero)`、`2B（尼尔：机械纪元）,2b (nier automata)`、`初音未来,hatsune miku`；
- 英文 tag 是提示词写法：用空格分词，去掉了冒号。它不等于 Danbooru 的真 tag（`rem_(re:zero)`、`2b_(nier:automata)`）。
- 我们用的底模是 v17，比清单晚一版。

## 要做

1. **数据**：
   - 下载 `https://raw.githubusercontent.com/mirabarukaso/character_select_stand_alone_app/main/data/waiIllustriousSDXL_v160_characters.csv`，放到 `.v2/data/wai/`；
   - 写一个 manifest，记录来源 URL、下载时间、sha256，以及"对应 WAI v16，项目底模是 v17"；
   - 加载时校验 sha256；
   - `tag_assist.json`、缩略图、`danbooru_e621` 词库本单都不接。
2. **中文名查角色**：解析角色名时，先查清单，查不到再走现有的 Danbooru 流程。
   - 取每行中文名第一个全角或半角括号之前的部分作为"名字"。输入和名字完全相等，或者和整行的中文名完全相等，才算命中。
   - 只命中一行，就用这行的英文 tag 去对 Danbooru 的真角色 tag：用现有的 Danbooru 查询拿候选，把清单 tag 和候选 tag 都规范化（小写，空格和下划线统一，去掉冒号）后比较，相等才算对上。对上了，就以 Danbooru 的真 tag 为准，后续流程照旧，外貌资料仍然从 Danbooru 取。
   - 命中多行，或者对不上 Danbooru 的真 tag，就走现有流程，不要猜。
   - 记录里要写明：命中了清单哪一行、对上了哪个 Danbooru tag。
3. **层级**：解析出的角色 tag 在清单里（按上面的规范化比较）时，直接判 L2，不出探针图。
   - 证据写明是清单命中，附清单版本、sha256 和行内容，以及"清单对应 v16，底模是 v17"。
   - 只在角色 LoRA 关闭时生效。打开时，L1 判定照旧。
   - 不在清单里的角色，层级判定流程完全不变。
   - 层级缓存：清单判定的结果可以不进缓存（不出图，重算很便宜）；如果要进缓存，键里必须包含清单的 sha256。
4. **开关**：加一个配置项指向清单文件，默认开启；关掉以后，行为和现在完全一样。
