## 背景（监工已核实，以 4139e1e 为准）

- `shot_contract.materialize`（约第 108–121 行）由 `pose` 和 `expression` 推导 `shot.tags = [pose, expression]`；`moment()`（约第 32–50 行）要求 `shot.tags` 只含 pose 和 expression；`extend_schema` 把 `tags` 的 `maxItems` 设为 2。
- `assembly.assemble_prompt`（约第 20–62 行）把 `shot['tags']` 按顺序接在构图 tag 后面，所以提示词末尾是 `…, cowboy shot, standing, surprised`。
- `tags.validate_tag_lists` 会对每镜的 `shot.tags` 做 Danbooru 存在性检查。
- 实验里的提示词是 `…, 姿势, 动作, 表情`，比如 `…, cowboy shot, standing, curtain grab, surprised`。

## 要做

1. **分镜字段**：beats 的 `shot` 新增可选字段 `action_tag`（一个原子 tag，格式同 `pose`）。不写或写 `null` 表示没有。`production_schema` 和 `beats-guide` 打印的 schema 都要有它。
2. **推导**：`materialize` 在有 `action_tag` 时推导 `shot.tags = [pose, action_tag, expression]`（去重，顺序不变）；没有时和现在完全一样。`moment()` 允许 `shot.tags` 里出现这一个 `action_tag`，`tags` 的 `maxItems` 改为 3。其余单时刻规则不变。
3. **提示词**：`assemble_prompt` 不用改顺序逻辑，按上面推导的 tags 自然得到 `…, 姿势, 动作, 表情`。确认是这个顺序。
4. **compile 检查**（`beats._collect_errors`，和其他逐镜检查放在一起，错误格式一致，字段 `shot.action_tag`）：
   - 和 `pose` 或 `expression` 相同：报错。
   - 是表情 tag（`EXPRESSION_TAGS`）：报错。
   - 已经出现在这一镜的 outfit tags、scene tags 或 prop_tags 里：报错。
   - Danbooru 上不存在，或者不是 general 类（category 0）：报错。存在性检查走现有的 `TagRegistry`，和其他 tag 一样走缓存。
   - 问题和改法的文字由你写，说清哪一镜、哪个值、该怎么改。
   - 这些检查只加在 `compile` 走的 `_collect_errors`；`validate_storyboard` 里只加 schema 和 `moment()` 自然带来的那部分，不加额外规则，旧任务续跑不受影响。
