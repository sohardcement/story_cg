# 工单 P10-01：v1 范围调整落地——道具降级、分镜规则、配饰不参与层级否决、SKILL.md 与使用说明

## 用户决定（摘要，以 PROGRESS.md 原文为准）

- D23：v1 只保证人物——身份、服装、表情、动作、单主角。道具归属、道具状态（烤焦、湿透等）、道具数量不再投入开发；覆盖 TASK.md §8 中"带关键道具的动作"剧情类型。
- D24：道具问题照常审核记录，只写入交付说明的已知问题，**不作为未通过的理由，也不为它触发修复**。
- D25：剧情关键变化优先由人物的表情和动作表现；每镜最多一个关键道具；剧情核心依赖道具归属或状态时照常出图、不额外提问，交付说明写明这部分可能读不出。通用约束，脚本校验，不针对特定角色。
- D19："拿错东西"类剧情作为已知局限，交付说明提醒（属于 D25 的"依赖道具归属"）。
- D20：配饰类项不参与层级否决；随服装变化的发饰归入服装状态（TASK.md §5），不算身份特征。
- D26：SKILL.md 与使用说明的示例换成人物动作、情绪驱动的剧情，并说明 v1 擅长和不擅长的剧情类型。

## 要做的事

1. **道具降级**（D23、D24）：结论归并与门禁中，道具类审核项（道具数量、持有、状态、接触）不再导致"未通过"，只进入交付说明的已知问题；修复对应表中去掉所有因道具问题触发的修复（含叙事修复里以道具为目标的分支）。离线测试锁住"道具 fail 不改变整组结论、不触发修复"。
2. **分镜规则**（D25）：
   - 运行时 LLM 在接收剧情时输出结构化字段（例如 `prop_dependent: true/false` 及一句理由，schema 约束，不用关键词表），为 true 时交付说明自动写入"本剧情的关键情节依赖道具归属/状态，v1 不保证能从画面读出"。不因此提问。
   - 分镜 schema/提示要求每镜的关键变化写在 expression / action 上；校验：每镜关键道具 ≤ 1（`role: key` 的道具数）；相邻镜头之间至少表情或动作之一有变化（无变化时要求给出理由字段，否则拒绝）。
   - 撤掉第二轮为"拿错"加的强制结构（possession_swap 的三条硬性要求），改为只在交付说明里提醒（D19）；`possession_swap` 字段可以保留作记录。
3. **配饰不参与层级否决**（D20）：层级门禁（tier_gate，冻结文件之外）中，accessories / hair_ornaments 类项不否决。身份资料抽取中，只出现在某套服装描述里、或在服装变体之间变化的发饰/配饰，归入该套服装的 outfit 状态，不进身份锁定 tag；只有 wiki 描述为角色固定特征的才留在身份里。用约尔的资料举例说明处理结果（白发带/金色花形发饰各归哪里、依据），但不写角色特例。补离线测试。
4. **SKILL.md 与使用说明**（D26）：示例换成人物动作、情绪驱动的剧情（例如"在山顶迎着朝阳伸懒腰，被风吹乱头发后有点生气，最后看着日出笑了"这类），并写清 v1 擅长：单主角的表情、动作、身份与服装一致、场景变化；不擅长：道具归属/状态/数量、两个具名角色同框、"拿错东西"类情节、远处小人物。同步更新 `tools/install_hermes_skill.sh` 不需要改（只是重装）；README/使用说明若有同类示例一并替换。SKILL.md 保持简短。
5. 用已有任务做离线回放（不出图、不调视觉模型）：`jobs/p9_06_cake`、`jobs/p9_07_ownership` 按新归并规则重新生成交付说明（`deliver`），展示道具问题已移入已知问题、整组结论如何变化。
