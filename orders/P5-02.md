# 工单 P5-02：自动修复循环 + 分镜规则补强，两组整组实跑

你是执行者，先读 AGENTS.md（含「监工补充禁令」），再读 TASK.md §6、§7、§9，`reports/P5-01.md` 与 `orders/P5-01.md` 末尾监工结论，以及 PROGRESS.md 中「审核器校准结果」一节。在现有代码上继续。

## 目标

把 P5-01 的修复原语串成 TASK.md §6 的自动修复循环，接进正式 CLI 的 `run`，并在两组完整剧情上实跑。

## 要做的事

1. **修复循环（脚本编排，状态落盘，可恢复）**：整组初次生成后，逐镜：
   - 审核（单张 + 跨图一致性，参考 = 定妆图）→ 按问题类型分类 → 选修复原语 → 执行 → 再审核 → 判断是否改善。
   - 问题类型 → 修复手段的对应表写在配置里（TASK.md §6）：身份漂移 → 面部精修（+加强参考）；动作不成立/手部 → 单镜重布局或改景别，再局部重绘；道具/持有关系 → 局部重绘或单镜重布局（可改分镜该镜的道具字段）；画面关系不清 → 改景别或机位；服装漂移 → 局部重绘并核对服装状态。
   - 运行时 LLM 只负责"解读审核结论 → 给出诊断与假设"，输出必须符合 schema，且只能从对应表允许的手段中选；脚本校验。
   - 每次修复记录"诊断 → 假设 → 改动 → 结果"。
   - **改善的判定**由脚本按确定规则计算（写进代码和配置）：以 `config/review_reliability.json` 中 reliable 项的 fail 数为主指标，unreliable/unverified 项的变化只记录、不作为"已改善"的依据。
   - 预算（配置，TASK.md §6 默认值）：每镜最多 3 轮修复；每组总生成 ≤ 40 张；每组 ≤ 45 分钟；某镜连续 2 轮没有改善就停止，保留最佳候选并标注问题。
   - 修完某镜后复核相邻镜头的服装与场景连续性；构图、重绘、放大后的最终图都要重新过身份和服装审核。
   - 整组最后跑盲审。盲审未读出关键事件/结局时，允许一次"叙事修复"：由 LLM 指出哪一镜缺了什么可见线索，按诊断改该镜并重出（仍受总预算约束）。
2. **分镜规则补强**（P3-02 的教训，通用规则写在配置/校验器里）：
   - 主角面部在大多数镜头可见：背影/遮脸镜头数不超过 1（除非用户剧情明确要求），校验器强制。
   - 需要"物体脱离人物"的瞬间（如东西被吹走、掉落），分镜必须把它拆成可静态读懂的画面（物体已在空中且与人物分离、人物伸手/回头），并把该道具的位置写成与人物分离；这是通用规则，不写具体物体名。
   - 其他人物只能以背影、路人、画面外、局部入镜出现，且不得出现来路不明的手（若出现手，分镜须说明是谁的手）。
3. **结果呈现**：交付说明（`runs/<job>/result.md`）里，逐镜列出最终结论（通过 / 有瑕疵但可选 / 未通过）、已知问题、修复历史摘要；对 unreliable/unverified 项明确写"该项未经可靠审核"。
4. **实跑两组**（全部走正式 CLI，默认 IPAdapter 0.4；布局模式由循环按需对单镜启用）：
   - `芙莉莲` / `下雨后在车站发现自己拿错了伞。`
   - `约尔` / `约尔下班路上，一阵大风吹走了她的帽子，她追了一路终于接住。`
   - 每组产出拼图，并与 P3-02 同剧情的"IPAdapter 0.4"组拼图并排 `review/P5-02-<角色>-前后.jpg`（左 P3-02，右 P5-02）。

## 必须产出

- 循环编排代码、配置、离线测试（预算与停止条件、无改善停止、只能选表内手段、改善判定只看 reliable 项、恢复不重复提交、相邻复核被触发、分镜新规则）
- 两组任务目录（含每镜修复历史、result.md、manifest 用量：累计生成张数、审核调用次数、耗时）
- `review/P5-02-芙莉莲-前后.jpg`、`review/P5-02-约尔-前后.jpg`
- `reports/P5-02.md`：两组的逐镜修复表、你看图的判断、与审核器不一致之处

## 验收标准（监工亲自看图）

- 两组都在预算内结束（manifest 用量可查）。
- 修复记录四段齐全；没有无诊断的换 seed。
- 监工看"前后"对照，判断身份、道具关系、叙事可读性是否改善。
- `uv run pytest -q` 通过。

## 不许做

- 不改冻结的审核器提示词与阈值、不改 reliability 配置、不改判。
- 不针对这两个角色或剧情写特例。
- 不装节点、不下载模型；不清空 ComfyUI 队列。
- 不 git commit，不写 `verify/`，不改 TASK.md / SUPERVISOR.md / PROGRESS.md / orders/ / AGENTS.md。

## 预算

- 出图上限 80 张（两组各 ≤ 40）；视觉调用上限 300；LLM 调用上限 60；时长 120 分钟。
