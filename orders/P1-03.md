# 工单 P1-03：三层审核器（初版）+ 面部裁切，并对 P1-02 的输出跑一次

你是执行者，先读 AGENTS.md，再读 TASK.md §7，以及 `reports/P1-01.md`、`reports/P1-02.md`。在现有代码上继续。

## 目标

实现 TASK.md §7 的三层审核（初版），并在 P1-02 生成的那一组图上实际运行，产出审核记录。审核器可靠性在 P4 由监工校准，本工单只要求实现正确、记录完整、结论规则正确。

## 要做的事

1. **视觉模型客户端**：模型服务 `http://127.0.0.1:11234/v1`（OpenAI 兼容，支持多图、json_schema）。每次调用把完整请求（图片可以只记录文件路径和 sha256，不必存 base64）、原始响应、耗时写入任务目录下的审核日志（例如 `runs/<job>/review_log.jsonl`）。
2. **单张审核**：人体、手部、动作、道具与物体接触、构图、画风。结构化输出（每项 pass / minor / fail + 理由）。
3. **跨图一致性审核**：
   - 身份逐项清单：发色、发型、瞳色、标志特征、发饰和配饰、服装各部件。清单条目来自 identity.json 与 outfit 状态，由脚本生成，不由模型自由发挥。
   - 面部裁切：ComfyUI 上**没有**面部检测模型（监工 P0 已核实：MediaPipe/Ultralytics 模型列表为空，禁止下载）。请在 ComfyUI 之外解决，例如让视觉模型返回面部 bbox 再用 Pillow 裁切；无论用什么办法，都要把裁切结果存成图片文件，让监工能直接看裁得对不对。
   - 把面部裁切与参考图（本工单还没有定妆图，暂用该组第 1 张的面部裁切作为参考，并在记录里注明"参考=第1镜，非定妆图"）并排比对。不要只问"是不是同一个人"。
   - 同时检查服装和场景状态是否与分镜中的 outfit / scene 状态连续。
4. **整组叙事盲审**：只按顺序提供图片，**请求里不得出现剧情、分镜、角色名或任何文字提示内容**，让模型复述看到的故事（在哪里 → 发生什么 → 人物如何行动 → 产生什么变化 → 结局如何）。再用**另一次**调用（这次可以带用户剧情）把复述与用户剧情对比，判断关键事件和结局是否被读出。
5. **结论三档**：通过 / 有瑕疵但可选 / 未通过。审核超时、解析失败或结论不明，一律按未通过处理（写成代码规则并有离线测试）。
6. `review <job目录>` 子命令：对已有任务跑三层审核，结果写 `runs/<job>/review.json`（以及人能读的 `review.md`），并更新 manifest 的审核记录与用量（审核调用次数、耗时）。
7. 对 P1-02 的任务目录实际运行一次。
