# 工单 V2-12：给写分镜的 agent 补上它需要的信息；词汇表撞键按表情区分；编译不再反复大批量查 Danbooru

监工派 Haiku 5.5 subagent 按 skill 文档为对比集写了第一批故事分镜（`verify/v2/beats/`，只读）。暴露出三个问题。工作目录、写入范围、git 规则同 V2-10（AGENTS.md 第 8、9、10 条）。

## 问题与证据

1. **写分镜的 agent 不知道角色的标准服装**。`plan_story` 会把 identity 里的 `default_outfit_tags` 交给模型，`beats-guide` 没有这一项。结果月城柳被写成 `pleated_skirt`（她穿的是黑色铅笔裙），芙莉莲被写成 `green_cape`。证据：`verify/v2/beats/g2-r1.json`、`g4-r1.json`。
2. **写分镜的 agent 看不到本层级的词汇表**。它不知道"近景正面擦眼泪"（第 15 项）本来就是稳定组合，写成了"近景坐着"，被改成中景，擦泪的特写丢了（g4-r1）。第 2 组为了凑名额，把结尾的"笑了"写成了"哭着擦泪"（g2-r1）。
3. **第 19、20 项撞键**：中景正面 standing，第 19 项配 expressionless，L1 是"有时"；第 20 项配 smile，L1 是"稳定"。现在命中只看景别、角度和 pose，撞键时取保守档，所以月城柳"中景正面站着笑"也算"有时"。这条规则是 V2-05 实现时定的，不是用户的决定。
4. **编译反复大批量查 Danbooru**：每次 `compile` 都会走 `frozen.live_inventory`，按 LoRA 清单批量查 Danbooru。4 个 agent 同时编译时触发了 429，层级被判成 `tier_pending_resources`，编译失败。证据：`.v2/compile/cmp-d14ddd72ad12/identity.json`。

## 要做

1. **`beats-guide --character C`（可选参数）**：给了角色时，额外打印两样东西：
   - 这个角色 identity 的标准服装 tag，加一句规则："剧情没换衣服时，服装 tag 原样用这几个；换衣服的镜头写新衣服的 tag"；
   - 本层级的词汇表段落，复用 `shot_vocab.prompt_section`，列出稳定、有时、不可用三档。

   层级只取缓存，不做探针、不出图；缓存未命中就写明"层级未知，按保守档"，并照常打印保守档的词汇表。`compile` 的输出（通过和不通过都算）也附上这两样。SKILL.md 改为"运行 `beats-guide --character '角色名'`"。
2. **撞键按表情区分**（监工决定 D57）：
   - 多个条目同时命中（景别、角度、pose 相同）时，若本镜 expression 只属于其中一部分条目的 `expression_tags`，就只按这部分条目定档；
   - 都不属于时，仍取保守档。
   - `classify_shots` 改这一处即可，编译、校验、观测回写都在用它。
   - 不改任何条目的分档。
3. **缓存层级判定前的 LoRA 清单查询**：`live_inventory` 的结果按 ComfyUI 报告的 LoRA 文件清单（文件名 + 大小）做键，存在 `cache/` 下，24 小时内复用，不再重复查 Danbooru；遇到 429 时退避重试，最多 3 次。缓存命中与否写进 `tier/` 下的记录。

## 验证

- 单元测试：
  - `beats-guide --character` 的输出含标准服装 tag 和词汇表；层级缓存未命中时提示保守档；
  - `compile` 的输出附带这两样；
  - 撞键：L1 中景正面 standing，配 smile 判稳定，配 expressionless 判有时，配 surprised 判保守档（有时）；
  - LoRA 清单缓存命中时不发起 Danbooru 请求（mock）；429 时退避重试。
- 全量测试通过。
- 离线：对 `verify/v2/beats/` 下已通过的 3 份 beats（只读）重新编译，对比改动前后的改写和分档。
