# 工单 P1-02：身份锁定 + 分镜 + 状态拼装提示词 + 4 镜出图 + 拼图 + manifest

你是执行者，先读 AGENTS.md，再读 TASK.md §4、§5、§6、§9，以及你自己写的 `reports/P1-01.md`。在 P1-01 的骨架上继续，不要另起炉灶。

## 目标

端到端跑通：输入"角色名 + 一句剧情" → 身份锁定 → 分镜（运行时 LLM，schema 校验）→ 从状态拼装提示词 → 出 4 张图 → 带编号的预览拼图 → manifest。这是最小闭环，身份控制（参考注入）、画风定参、修复循环、审核器都在后续工单做，本工单不做。

## 要做的事

1. **身份解析（最小版）**：`resolve` 子命令，输入角色名（中文/英文/tag 都可能），通过 Danbooru 查出候选角色 tag。
   - 可用接口（监工已验证可访问）：`https://danbooru.donmai.us/autocomplete.json?search[query]=<名字>&search[type]=tag_query&limit=10`（中文别名也能命中，例如"菲伦"→`fern_(sousou_no_frieren)`）；`/wiki_pages/<tag>.json`；`/tags.json`；`/related_tag.json`（共现 tag 统计）。请求带 User-Agent，注意限速，结果缓存到工作目录。
   - 产出 `identity.json`：锁定的角色 tag、作品 tag、外貌 tag 列表、每一项的来源（URL + 取得方式）。外貌 tag 只能来自资料源（wiki 正文、共现统计等），不能由 LLM 凭印象生成。候选无法区分时不要自动选，返回候选列表并标记需要提问（本工单只需把这个分支做出来，完整消歧在 P6）。
   - 层级判定本工单只写占位字段，P6 再做。
2. **分镜（运行时 LLM）**：`plan` 子命令调用模型服务，把剧情拆成 N 镜（默认 4–6，本工单用 4）。输出必须符合 JSON schema 并由脚本校验，校验失败重试有上限。schema 至少覆盖 TASK.md §5 的 outfit / scene / shot 字段：
   - scene：地点、时间、天气、光线、环境状态变化
   - outfit：服装状态，以及换装发生在哪一镜
   - shot：叙事作用、主体动作、表情、关键道具（在谁手里、放在哪里）、空间关系、景别、机位、相对上一镜的变化
   - LLM 不得输出角色外貌词；脚本要检查并拒绝（例如在 shot/scene/outfit 字段里出现发色、瞳色等外貌词时判为不合格）。这条检查不能针对具体角色写词表特例，要通用。
   - v1 只保证一个具名主角，其他人物用背影、路人、画面外、局部入镜表现（TASK.md §9）。
3. **提示词拼装**：由脚本从 identity / outfit / scene / shot 状态拼装：原样身份块 + 服装块 + 场景块 + 镜头块。身份块逐字复用，所有镜头完全一致。分辨率按景别从配置取。
4. **run**：`new`（或同类命名）建任务 → resolve → plan → 逐镜出图（沿用 P1-01 的先落盘再提交、可恢复规则）→ 拼图 → manifest。
   - 预览拼图：每张图左上角大号编号（1、2、3…），按顺序排列，存 `runs/<job>/contact_sheet.jpg`，并复制到 `review/<角色>-<剧情简称>.jpg`。
   - manifest：模型文件与可得的哈希（ComfyUI `/view_metadata/loras?filename=` 可取到部分 LoRA 的 `sshs_model_hash`；checkpoint 取不到时标注 unavailable；可附 `/experiment/models/<folder>` 的 size/mtime）、LoRA 与权重、每张图的完整提示词、seed 与参数、prompt_id、输出文件 sha256、用量（出图张数、LLM 调用次数、耗时）。
5. **真实运行一次**：角色用 `芙莉莲`（中文名输入，走 resolve），剧情 `下雨后在车站发现自己拿错了伞。`，4 镜。
6. **恢复规则修正（P1-01 遗留）**：现在 `submitting` 状态且 `/queue` 与完整 `/history` 里都找不到同 prefix 记录时，会停在 `uncertain`、不再重投。这会让无人值守的恢复卡住。改为：重新拉取一次 queue 和完整 history 复核，两处都没有同 prefix 记录时视为"确认未提交"，用**同一个** filename_prefix 重新提交（prefix 唯一，所以不会产生重复）；history 明确失败时记录失败原因，并按新的 attempt 编号重新提交。补对应的离线测试。
7. **自评**：本工单不要求实现审核器，但你要自己查看生成的 4 张图，按 TASK.md §7 的三层（单张 / 跨图一致性 / 只看图能否读出剧情）逐张写观察，写进报告。如实写问题，不要美化。
