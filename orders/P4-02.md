## 第一步：通用修正（只针对以下已知问题）

1. **不可观察项**：必需项在画面中看不到（例如上半身图里的靴子、远景里只有几个像素的瞳孔）时，审核器却判 pass。改为引入 `not_visible` 状态：模型必须先回答该项是否可见，不可见时不得给 pass。归并规则：身份/服装必需项 `not_visible` 记为"未经审核"，在结论中单独列出，不能算通过；若一组图里某个必需身份项在所有镜头都不可见，整组身份层判未通过。
2. **道具数量与状态**：审核器多次漏掉"多画了一把伞""伞应闭合却打开"。改为脚本从 props 状态和 shot 的 key_props 生成逐项清单：每件关键道具应出现的数量、持有者/位置、状态（开/合等，若 storyboard 有），让模型逐项数数并回答。清单来自任务状态，不写死任何道具名。
3. **景别**：多次把近全身判成符合 medium。改为让模型先描述画面中人物可见范围（头到哪里），再由脚本按配置的景别定义判断是否匹配，而不是问模型"是否符合 medium"。
4. **bbox 坐标**：模型有时返回像素坐标而非 0–1 归一化值，被 schema 拒绝导致整镜失败。若返回值明显是像素坐标（>1 且不超过图片尺寸），按图片尺寸换算并在日志中记录换算；其它非法值仍判失败。
5. 修正后跑离线测试，然后**冻结**：记录 `src/storycg/review.py` 及所有审核提示词文本的 sha256 到 `calibration/reviewer_freeze.json`。之后本工单内不得再改审核器。

## 第二步：校准运行

1. 真值文件 `verify/P4-labels.json` 是**逐项**真值（每个样本、每个审核项：error / ok / not_visible / ambiguous），不是整张样本对错。先读它的 `_about`、`_item_mapping`、`_layer_rule`。只使用 `confirmed: true` 的样本；`ambiguous` 的项不统计；被剔除的样本（E1b）在报告里列出。
2. 每个样本**两层都跑**：跨图一致性（参考 = 该角色定妆图；身份/服装清单由脚本从该角色 identity/outfit 生成）和单张审核（带该样本 json 里的分镜要求 shot_requirement 与 props）。每个样本跑 **2 次**。
3. 统计（按 `_item_mapping` 把审核器的项映射到真值项）：
   - 检出率：真值为 error 的（样本, 项），审核器在对应项给出非 pass（fail / minor / not_visible 都算"未放过"，但分别计数，报告里分开列）。
   - 误报率：真值为 ok 的（样本, 项），审核器在对应项判 fail。
   - not_visible 处理：真值为 not_visible 的项，审核器判 pass 记为"不可见却放过"，单独统计。
   - 两次运行结论不一致的比例。
4. 按以下规则生成 `config/review_reliability.json`（规则写进代码，不要手填结果）：某审核项的检出率（只算 fail）≥ 75% 且误报率 ≤ 20%，且该项至少有 3 个 error 样本和 3 个 ok 样本 → `reliable`；样本数不足 → `unverified`；否则 `unreliable`。
5. 运行时接入：审核结果（review.json / review.md / manifest 的审核记录）中，`unreliable` 和 `unverified` 的项必须标注"该项未经可靠审核"（TASK.md §3 P4）。这些项即使判 pass，也不能作为交付说明里"已验证"的依据。
