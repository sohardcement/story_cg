# 工单 V2-14：闭眼镜头不审瞳色；修图不得让原本通过的可靠项退化

对比集第 4 轮里，结尾"睡着"那一镜被修图改成了睁眼。工作目录、写入范围、git 规则同 V2-10（AGENTS.md 第 8、9、10 条）。

## 问题与证据

第 1 组 r1 第 4 镜，任务目录 `.v2/jobs/cg-e65914ca08fb`，只读：

1. 分镜要求 `on_back` + `sleeping`，拼装时自动补了 `closed_eyes`。首轮出图 `shot04_a001` 闭眼、戴眼镜，正确。
2. 一致性审核把瞳色判成 **fail（reliable）**，理由是"闭着眼，看不到粉色瞳色"（`cycle_artifacts/initial_4.json`）。
3. 诊断选了 instruction_edit，把瞳色改成 `pink_eyes`（`decision_4_1_contract6.json`）。
4. 修图结果 `shot04_a002`：眼睛睁开，眼镜没了。候选图审核（`repair_4_1.json`）的结果：
   - 动作从 pass 变成 **minor（reliable）**，理由是"要求睡着，但眼睛睁着看向镜头"；
   - signature_features 变成 fail（unverified，眼镜不见了）；
   - 瞳色变成 pass。
5. 改善判定只比较"可靠 fail"的数量。这里从 1 降到 0，所以判为改善，交付了睁眼、没眼镜的那张。

这里有两个缺陷：
- 分镜本来就要求闭眼，这时瞳色根本无从判断，不应该审，更不应该当成 fail 去修；
- 修图让原本 pass 的可靠项退化成 minor，仍被当成改善。

## 要做

1. **闭眼镜头不审瞳色**（监工决定 D58）：
   - 判断依据：某镜的 pose、expression、tags，加上 `prompt_rules.companion_tags_for_shot` 补出的 tag，canonical 后含 `closed_eyes`，就算"分镜要求闭眼"。
   - 这时一致性审核不再请求瞳色这一项，在审核记录里写成 `not_applicable`，原因是"分镜要求闭眼"。它不计入 fail，也不会成为修图对象。
   - 这不是放宽阈值：分镜要求闭眼时，瞳色这一项本身没有定义。
   - 其他身份项照旧审。只闭一只眼（`one_eye_closed`）不算闭眼。定妆图不受影响。
2. **修图候选不得让可靠项退化**：
   - 在候选图的改善判定里加一条：源图和候选图都有的同一项，源图是 pass，候选图变成 minor 或 fail，而且候选图这一项是 reliable，就判为没有改善。
   - 原因写进修复记录，例如"action: pass → minor（可靠项退化）"。
   - 现有的"可靠 fail 严格减少"条件保持不变，新条件是额外的一道。

## 验证

- 单元测试：
  - 要求闭眼的镜头不请求瞳色，记成 not_applicable，三种来源各一个：expression 是 sleeping，经 companion 补 closed_eyes；pose 直接写 closed_eyes；tags 含 closed_eyes。
  - 睁眼镜头照常审瞳色。
  - `one_eye_closed` 照常审瞳色。
  - 可靠项从 pass 变成 minor 时，候选不算改善，即使可靠 fail 数在下降。
  - 不可靠项退化不受新条件影响。
- 全量测试通过。
- 离线回放（只读，不写任务目录）：
  - 用 `cg-e65914ca08fb` 的 `initial_4.json` 和 `repair_4_1.json`，在改动前后各算一次候选改善判定。确认改动前是 True，改动后是 False。
  - 扫一遍 `.v2/jobs/*/cycle.json` 里所有被判为改善的修复，按新条件重算。列出会被改判的修复：任务、镜号、问题、方法、退化的项；
  - 再列出：所有在要求闭眼的镜头上、以瞳色为问题做的修复。
