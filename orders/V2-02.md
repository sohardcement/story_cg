# 工单 V2-02：第二批删减（上）：分镜与接收层的道具分支

先读 `TASK-v2.md`（§0、§2.2 第 6 条、§4 第二批、§8）、`audit/AUDIT.md` 里对应模块的行，以及你自己的 `reports/V2-01.md`。

工作目录、写入范围、提交规则同 V2-01：只写 v2 工作树，不写主线工作区，不 git commit。

## 背景

D23–D25 和 TASK-v2 §0 已把道具降为陪衬：分镜里可以出现道具，每镜最多一个；它只作为场景或镜头 tag 写进提示词，不登记、不绑定持有者、不跟踪状态、不审核、不修复。

本单拆掉分镜与接收这一层只为道具服务的协议。审核、修复和拼装层留给 V2-03。

## 要拆的部分（以 AUDIT.md 为线索，以你的静态检查为准）

| 模块 | 拆掉 | 保留 |
|---|---|---|
| `planning.py` | PROP/PROP_STATE 协议、道具登记去重、holder/owner/state、同类物体对照、possession_swap 锁定 | 单瞬间、单主角、景别、服装和外貌隔离；**每镜最多一个道具**的校验 |
| `shot_contract.py` | owner、distinguish_ownership、establishes_ownership、distinguishing_features_visible、possession_swap 及 owner 一致性 | 单姿态、单表情、单主角、倒影 |
| `story_rules.py` | key_props 的 detached_separation / detached_reaction 等物体脱离、持有叙事规则 | 主角可见、匿名他人、手的归属、遮挡和浮空手规则（other_holder 里涉及匿名人物的部分保留） |
| `agent.py` 接收协议 | INTAKE_SCHEMA 的 possession_swap、prop_dependent、prop_only_narrative_items 及相应的道具语义判断 | 改成一句范围提醒：道具只作陪衬，数量、归属、状态不保证 |
| `pipeline.py` | 只为道具服务的参数传递 | 其余全部 |

## 要求

- **分镜里出现的道具**怎么处理：
  - 仍然写进该镜提示词，形式是普通 tag；
  - 每镜超过一个就校验失败，沿用现有的失败与重试机制。
- **接收协议**：遇到"拿错东西""认错人"这类靠道具归属推理的剧情（TASK-v2 §0、D35 第 8 项），在分镜阶段改写成能用表情和动作表达的版本，并在任务记录里留一句说明，后面交付说明会用到。
- **交付说明**（`result.md`）固定加一句"道具未经审核"。
- **兼容旧任务**：已有任务目录里带道具字段的历史记录，`status` 和 `deliver` 仍能正常读取和生成，不报错。
- **测试**：
  - 只为被删协议服务的测试一起删；
  - 为新行为补测试：超过一个道具时校验失败、交付说明里有那句话、旧任务目录能读；
  - 其他测试不得改弱。
- 删完后：
  - 全量测试通过；
  - CLI 各子命令的 `--help` 正常；
  - 对一个已有任务目录离线跑 `status` 和 `deliver`（先复制到工作树里）。

- 写主线工作区；
- 出图；

- git commit。
