# 工单 P6-01：通用角色流程（上）——名字消歧、原设资料抽取、L1/L2 层级判定

你是执行者，先读 AGENTS.md（含「监工补充禁令」），再读 TASK.md §4、§9（提问规则），以及 `reports/P1-02.md`、`reports/P3-02.md`、`orders/P3-02.md` 末尾监工结论。在现有代码上继续。

## 背景

- `resolve` 目前靠 Danbooru autocomplete + wiki 正文里的链接抽外貌 tag。P3-02 发现约尔的 identity 只有 `long_hair, black_hair, single_hair_bun`，缺了红瞳、白发带、金耳饰等关键特征，服装只有 `sweater_dress, black_dress`。身份资料不全会让身份块、定妆图和审核清单都跟着缺项。
- 层级字段一直是 `pending_P6`。

## 要做的事

1. **名字消歧**：中文名/别名/英文名/tag → 候选作品与角色 → 标准 tag。
   - 数据源：Danbooru autocomplete（含 other names）、`/tags.json`、`/wiki_pages`；必要时中文维基搜索（P0 已验证可访问）辅助确认作品。
   - 多个候选无法区分时，返回 `needs_clarification` 与候选列表（每个候选：tag、作品、post 数、一句依据），不得自动挑。这是 TASK.md 允许向用户提问的情形。用户可用 `作品名` 或直接给 tag 来消歧（CLI 参数）。
   - 离线测试：单候选、多候选需提问、带作品名消歧、直接给 tag。
2. **原设资料抽取（补全）**：在 wiki 正文之外，加入 Danbooru 共现统计作为来源——例如 `/related_tag.json?query=<角色tag>&category=general` 的共现频率。规则通用：发色、瞳色、发型、标志特征、常见配饰按**类别**取共现频率超过阈值（阈值写在配置里）的 tag；同类互斥的（例如两个发色）只取最高且显著领先的，否则标记为冲突并不锁定。每个 tag 记录来源（URL、方法、频率）。
   - 服装：同样从共现统计与 wiki 抽取"常规服装"候选，但服装多套时要保守：只锁定高频且互相兼容的部件，其余记为候选。
   - 生成的图和搜集到的参考图**不能**作为原设证据（TASK.md §4）。
   - 身份块由脚本从锁定结果拼出，运行时 LLM 不参与。
   - 离线测试：共现阈值、同类冲突不锁定、来源必填。
3. **层级判定 L1 / L2**（L3/L4 在 P6-02）：
   - L1：本地有该角色专用 LoRA。通过 ComfyUI `/object_info` 的 LoRA 列表 + `/view_metadata/loras` 的训练 tag 频率（`ss_tag_frequency`）匹配角色 tag，文件名只作辅助。匹配到后在生成 workflow 中加载该 LoRA（权重、触发词写配置/从元数据取），并与画风 LoRA 共存。
   - L2：没有 LoRA，但底模认识该角色 tag。**必须**用测试生成 + 与可靠参考比对来验证：
     - 测试生成：只用身份块 + 中性构图，**不注入任何参考图**，1–2 张。
     - 可靠参考：从 Danbooru 取该角色 rating:g、高分的若干张图（记录 post id 与 URL，下载到任务目录的 `references/`）。这些图只用于"底模是否认识"的比对，不作为原设证据。
     - 比对：用视觉模型按身份清单逐项比对测试图与参考图；只有 `config/review_reliability.json` 中 reliable 的项才能作为判定依据，其余项在记录中标注"未经可靠审核"。
     - 通过则判 L2，否则进入 L3/L4 流程（P6-02；本工单先返回 `tier_pending_L3_L4`）。
   - 判定证据（LoRA 匹配依据、测试图路径、参考 post、比对结果）写入 identity.json 的 `tier_evidence`。
4. **真实运行**（resolve + 层级判定，不出剧情图）：
   - `菲伦`（预期 L1：本地有 `Fern_Frieren_Beyond_Journeys_End_-_Illustrious_V2.safetensors`）
   - `月城柳`（预期 L1：本地有 yanagi 相关 LoRA；多个文件时说明选择依据）
   - `芙莉莲`（预期 L2）
   - `约尔`（预期 L2；检查补全后的身份资料是否含红瞳等关键特征）
   - `爱丽丝`（一个故意的歧义名，预期返回候选并要求提问，不出图）
   "预期"只是监工的假设，按实际证据判定，如实报告，不要为了符合预期调整规则。
