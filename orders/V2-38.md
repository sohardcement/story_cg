# 工单 V2-38：只支持 WAI 清单里的角色，删掉层级探针和 L3 参考图路线

用户决定（D75）："不在清单里就别折腾了"。D76 的对照实验结论是保留现在的提示词写法，本单不动提示词。

工作目录、写入范围、git 规则同前，遵守 AGENTS 第 9、11 条。命令带 `PYTHONPATH=$PWD/src`。

## 要做

1. **清单外的角色直接停下**：身份解析锁定角色 tag 之后，如果角色不在 WAI 清单里（规则和 `wai_list` 现有的规范化比较一致），就不再跑层级探针。
   - 直接返回 `needs_user`。`reason` 写一个明确的值，比如 `character_not_in_wai_list`。
   - `question` 写成用户看得懂的话："这个角色不在 WAI 角色清单里，底模多半画不好，建议换一个清单里的角色"，再附上清单文件路径和版本说明。
   - `compile`、`make`、`beats-guide` 都按这个口径走。`beats-guide` 不报错，只在输出里说明"不支持"。
2. **删掉只为清单外角色服务的代码**：
   - L2 的层级探针，也就是不带 LoRA、只给角色 tag 出一张探针图再比对外貌那一套；
   - L3（IPAdapter 参考图注入、L3 定妆图、`reuse_l3_portrait`）和 L4 的整条路线（`fallback.py` 里的相应部分）；
   - `tier_cache` 里只给探针结果用的部分；
   - `identity_rules.json` 里 `tier_probe` 等只给这些路线用的配置；
   - 以及对应的测试。
   - 删之前先在报告里列出调用关系：谁调用谁、哪些函数还被保留的路径用着。比如 `identity.py` 从 `fallback` 引入的 `needs_user`，要挪到合适的地方，不能删。
3. **要保留的**：
   - 所有角色每镜都用 IPAdapter 把定妆图的脸作参考（强度 0.4）。这是 identity_control，不是 L3 路线，必须保留，而且行为不变。
   - L1 角色 LoRA 的代码默认关闭，按 D62、D75 保留。
     - 如果 L1 的判定离不开探针比对，就保留它需要的最少部分，放在开关后面，并在报告里写明保留了什么、为什么。
     - 如果没法做到，就停下来写进报告，不要擅自删掉 L1。
   - WAI 清单判 L2 的逻辑。
4. **SKILL.md**：写明只支持 WAI 清单里的角色，以及遇到 `character_not_in_wai_list` 时怎么转告用户。不要扩写其他内容。
5. 词汇表里 L3、L4 相关的取档说明，如果只剩死代码，也一起清理掉。
