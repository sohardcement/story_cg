# 工单 V2-33：第二次实测剩下的 5 个问题

依据是另一个 agent 的第二次实测报告。它用初音未来跑了一组换装剧情，报告在 `.v2/reports/story-cg-regression-20261010-final.md`，任务目录是主线工作区的 `jobs/cg-464a13b93b61`（只读）。报告里写明已经生效的部分，这次不用再动。

工作目录、写入范围、git 规则同前，遵守 AGENTS 第 9、11 条。命令带 `PYTHONPATH=$PWD/src`。

## 要修的（监工已逐条核实）

1. **`compile` 遇到 Danbooru 500 时，直接输出 traceback，没有输出 JSON。**
   - `make` 遇到同样的错误时，`status` 能正确返回 `needs_user`，报"关键资源不可用"；`compile` 走的路径没有处理这种情况。
   - 改成：资源错误（HTTP 错误、网络断开）时输出一个 JSON，包含 `status`、`reason`、`question`，和 `make` 的口径一致，同时以非零码退出，stderr 不再出现 traceback。
   - `beats-guide`、`resolve` 也查一遍，有同样的问题就一起修。
2. **报错文字不对。**
   - 写身体部位的字段（`spatial_relation`、`change_from_previous` 等）只能是一个动作子句，违反了这条规则时，现在报的是"外貌描写"，可同时又说眼睛状态和体位动作是允许的。实测的 agent 因此误判了原因。
   - 改成按实际违反的规则分别报错：
     - 真写了外貌（颜色、发型、体型），报外貌描写；
     - 违反"单个动作子句"，报"这个字段只能写一个动作子句"，并说明怎么改。
   - 校验规则本身不改，只改报错文字。
3. **进度提前计数。**
   - `agent._progress` 在 `candidates.json` 还没写出来时，会退回旧的算法，按"已出图的镜数"计数。
   - 首张候选出完、候选文件还没写的那一分钟里，就会显示 `completed_shots=1`、`shots` 为空。
   - 修图交付已经删除，任务都是候选交付。改成：候选交付的任务里，`completed_shots` 永远等于已挑选的镜数；候选文件还没写的时候，就按"0 张已出图、0 已挑选"给出每镜的条目。
   - 旧算法只留给确实没有候选交付配置的历史任务，判断依据是任务配置，不是 `candidates.json` 存不存在。
4. **定妆图失败原因漏报。**
   - 初音这次的定妆图原始结论是"未通过"，原因不在审核数据里，而在检测项里：`detection_items.accessory_color_sampled` 的状态是 `not_visible`，原因是 `no setting reference`。
   - `display.portrait_review` 只读审核数据，所以 `failed_items` 是空的，`result.md` 写成了"未记录具体项"。
   - 改成：把检测项里导致未通过的条目也列出来，并标出是不是可靠项。
   - 审核结论的规则不改，只改展示。
5. **颜色归一没覆盖到 aqua 等颜色。**
   - `tags.py` 的 `COLOR_WORDS` 只有 14 种颜色，没有 aqua、teal、cyan、navy、beige 等。所以初音的 `aqua_necktie` 和 `blue_necktie` 两个都被锁定了。
   - 改成用 Danbooru 的颜色 tag group 作为颜色表（`cache/tag_groups/` 下已经有别的组的快照，照同样的做法取一份 colors 组的快照，带 sha256）。手写清单只作为补充。
   - 用 V2-31 的 7 个角色身份夹具，加上灵梦，回放一遍，列出改动前后标准服装的变化。预期：初音的领带只留一个，其余角色的变化逐条解释。
