# 工单 V2-10：故事分镜输入（第一段由 agent 写，流水线不再调用本地模型做分镜）

先读 `TASK-v2.md` §9（方向调整，本单的依据）、§2.2，以及 `AGENTS.md`（尤其第 8、9、10 条）。工作目录是 v2 工作树 `/work/workspace/manga_skill/.v2`（分支 `v2`）。所有读写都只在这个目录内，不要动主线工作区的其他路径。

## 背景

目前 `agent.execute` 在 `planning` 阶段调用 `planning.plan_story`。这个函数让本地小模型写分镜 JSON（schema 由 `shot_contract.planner_schema` 生成），校验不过就把错误发回去重写，最多 5 次。按 §9，改成两段：

1. 调用 skill 的 agent 先写好"故事分镜"JSON，以文件形式交给流水线；
2. 流水线用代码把它编译成正式分镜，不再调用本地模型。

本单只打通第一段的输入路径和"编译"框架。词汇表自动改写等确定性改写规则放到下一单 V2-11。

## 要做

1. **故事分镜的格式**：沿用现有的 planner JSON 格式，也就是 `plan_story` 期望模型输出的那份（`planner_schema(production_schema())`），不另起一套。新增 `storycg beats-guide [--shots N]` 命令，打印一份给 agent 看的写作说明，内容包括：
   - 这份 JSON schema；
   - 现在 `plan_story` 系统提示词里的全部写作规则（不许写外貌、每镜最多一个道具、pose 只填体位、状态放进 expression 等）；
   - 首镜规则。
   把系统提示词里的规则文本抽成一个函数，`plan_story` 和 `beats-guide` 共用，内容不变。词汇表那一段因为依赖层级，`beats-guide` 里不放。
2. **首镜规则撤回 D52**：首镜必须是 `wide` 加 `establishing`（恢复 295e28d 之前的校验和提示词）。`tests/test_p1_04.py` 和 `tests/test_v2_08.py` 里与 D52 有关的断言，改回"首镜 medium 报错"。
3. **编译函数** `compile_beats(job_dir, beats, identity, shot_count, config)`，放在 `planning.py` 或一个新模块里。它要按顺序做完现在 `plan_story` 拿到模型输出之后做的所有事：
   - schema 校验；
   - `materialize`；
   - `validate_storyboard`；
   - Danbooru tag 校验（`TagRegistry`、`validate_tag_lists`）；
   - 词汇表校验（`validate_shot_vocab`）；
   - 剧情规则（`validate_story_rules`）；
   - 推导 `change_at_shot`。

   通过就保存 `storyboard.json` 并返回分镜。不通过就抛出一个异常，带上全部错误（尽量一次列全，不要只报第一条），每条写明是哪一镜、哪个字段、怎么改。
   - 编译过程**不调用**任何模型。
   - 编译日志写进 `plan_log.json`：`planning_contract` 标为 `beats_compiled_v1`，记录输入文件的 sha256 和错误列表。
4. **CLI 和 agent 入口**：
   - `storycg make` 新增 `--beats FILE`：给了就在 `planning` 阶段走 `compile_beats`，不调用 `plan_story`。
   - 编译失败时：任务停止，phase 为 `stopped`，`error` 写出全部错误。要求 agent 修改 beats 文件后重新 make，或者用下面的 `compile`。
   - 新增 `storycg compile --character C --beats FILE [--shots N]`：只解析身份、判定层级（优先用缓存）、编译，打印编译后的分镜或全部错误，不出图。层级缓存未命中时，按现有流程做层级判定，可能出 1 张探针图，要在输出里说明。
   - 不给 `--beats` 时的行为暂时保持不变，下一阶段再决定是否删除。
5. **skill 文档**：更新 `skill/story-cg-v1/SKILL.md`，写明新流程：
   - 先运行 `beats-guide` 读说明，写好 beats 文件；
   - 用 `compile` 自查，有错误就改，直到通过；
   - 再 `make --beats`。

   只改文档，不改安装脚本。

## 验证

- 单元测试：
  - `beats-guide` 的输出含 schema 和规则；
  - 合法的 beats 能编译通过，并写出 `storyboard.json`，内容和走 `plan_story` 得到的同一份分镜一致：用一份固定的模型输出做夹具，两条路径比对；
  - 有多处错误的 beats 能一次报出所有错误，每条带镜号和字段；
  - 编译过程不发起任何 HTTP 模型调用：mock 掉 `model_service_url`，断言没被调用；
  - 首镜 medium 报错；
  - `make --beats` 走编译路径，用现有的假服务集成测试方式，参考 `tests/test_v2_05.py` 的 execute 集成测试。
- 全量测试通过；CLI `--help` 正常。
- 离线演示：用 `.v2/jobs/cg-b42fae34baa4/plan_log.json` 里通过那次调用的 `raw`（只读）当 beats 输入，跑一次 `compile`。层级用缓存，不出图。把输出贴进报告。
