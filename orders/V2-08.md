# 工单 V2-08：分镜收敛（对比集第 1 组卡在分镜）

监工用 v2 跑对比集第 1 组（月城柳，捡小猫后睡着），**分镜 5 次调用全部被拒，任务停止，一张剧情图没出**。v1 基线同一剧情第 4 次调用通过；v1 基线第 4 组（芙莉莲，哭后擦眼泪）也是同类原因失败。证据：

- v2 第 1 组：`.v2/jobs/cg-b9352a5f6f2a/plan_log.json`
- v1 基线：主线 `jobs/cg-e1f1228a3ecb/plan_log.json`（第 1 组）、`jobs/cg-c0b1a7c8fffc/plan_log.json`（第 4 组）。只读。

5 次被拒的原因：

| 次 | 原因 |
|---|---|
| 1–3 | `outfit change_at_shot must name the current shot`：模型在第 1 镜就写 `change_at_shot: 3`（预告第 3 镜换睡衣） |
| 4 | `appearance description is forbidden in storyboard: eyes closed, sleeping`：把眼睛的状态当成外貌 |
| 5 | `shot_vocab_sometimes_limit`：第 1 镜中景正面 standing 是"有时"；第 4 镜 pose 写成 `sleeping`，它不是姿势，词汇表里查不到，按表外算，又占了一个"有时"名额 |

v1 第 4 组 5 次全部是 `appearance description is forbidden ...: wiping_eyes`。

开工前先读：`TASK-v2.md` §2.2，`.v2/reports/V2-05.md`、`.v2/reports/V2-06s.md`。工作目录、写入范围、git 规则按 AGENTS.md 第 8、9 条执行。

## 要做

1. **`change_at_shot` 不再作为拒绝理由，由代码推导**。规则：第 1 镜为 null；之后每一镜的服装 tag 集合和上一镜不同时，取本镜号，否则为 null。模型写的值一律不用，可以从 planner schema 里拿掉。在 plan_log 里记下"模型原值 → 推导值"。先查清下游哪些地方读这个字段，确认推导后行为不变，写进报告。
2. **眼睛的状态和对眼睛的动作不算外貌**。闭眼、半闭眼、单眼闭、擦眼睛、揉眼睛、擦眼泪、流泪这一类 tag 和短语，应该通过外貌检查。眼睛的颜色、形状、大小，以及其他外貌描述，仍然拒绝。
   - 判定依据用 Danbooru 的 eyes tag group（`tag_group:eyes_tags`），按 posture 组的做法存快照，配置里写来源 URL 和 sha256。不要自己手写一份清单冒充来源。
   - 自由文本短语（例如 `eyes closed`、`wiping eyes with hand`）按同样的语义放行：状态词或动作词作用在眼睛上就放行，带颜色、形状这类属性的照样拦下。
3. **姿势和状态分开**。
   - 词汇表里，"睡着"是表情（第 6、8 项的 `expression_tags`），姿势是 `on_back` 这类体位。
   - 分镜提示词要写明：`pose` 只能填体位；睡着、哭这类状态放进 `expression`。
   - 词汇表命中判定保持不变。
   - V2-06s 的伴随 tag 规则（睡着必带闭眼）目前只看 `pose`，改为 `pose`、`expression`、`tags` 任一处出现都触发；冲突校验同样覆盖这三处。
   - 超出"有时"名额的报错信息里，加一句可操作的修改建议：表外的 pose 如果是状态，就移到 expression，换一个表内体位。
4. 不改"有时"名额、词汇表分档、审核阈值和调用上限（仍是 5 次）。不针对测试剧情或角色写特例。
