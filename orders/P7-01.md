先读 AGENTS.md（含「监工补充禁令」），再读 TASK.md §5（SKILL.md 要求）、§9（运行时体验、提问规则、交付内容），以及 PROGRESS.md「P0 环境报告」里的 Hermes 一节。在现有代码上继续。

## Hermes 事实（监工 P0 核实）

- Hermes Agent v0.21.5，skill 放在 `~/.hermes/skills/<目录>/SKILL.md`（frontmatter 含 `name`、`description`），自动成为 `/<name>` 斜杠命令；非交互调用 `hermes -z "<prompt>" --skills <name>`。
- Hermes 当前模型是 `Qwen3.8-Flash-Next-Uncensored-MLX-Serve-4bit`（与我们的视觉/分镜模型同一个服务）。它通过终端工具执行命令。
- **安装和 Hermes 实测由监工做**（需要写 Hermes 目录）。你只在工作目录里准备好待安装的 skill 目录和安装脚本，不要写 `~/.hermes`。

## 要做的事

1. **统一入口命令**（在现有 CLI 上加一层，面向 agent 调用；输出机器可读 JSON 到 stdout，进度到 stderr）：
   - `make --character <名字> --story <剧情> [--shots N] [--storyboard-first]`：默认全自动（识别角色 → 分镜 → 定妆 → 出图 → 审核 → 修复 → 交付），立即返回 job 目录，并在后台继续运行（或提供 `--foreground`）；`--storyboard-first` 时只做到分镜，返回简洁分镜（每镜一两句中文）并停下。
   - `approve <job> [--edit <分镜修改说明或文件>]`：先看分镜模式下，用户确认/修改后继续出正式图；修改说明交给运行时 LLM 改分镜并重新过 schema 校验。
   - `status <job>`：阶段、进度、已用张数/调用/耗时、是否需要用户回答问题。
   - `resume <job>`：中断恢复（沿用已有对账规则，不重复提交）。
   - `deliver <job>`：重新生成交付物（不出图）。
   - 需要提问的情形（且只有这些）：角色身份无法确定（返回候选）、关键资源不可用（例如 ComfyUI 不可达、所需模型缺失）、用户要求互相冲突。用统一的 JSON 字段表示（例如 `{"needs_user": true, "reason": "...", "question": "...", "options": [...]}`）。剧情中出现多个具名角色时，告知 v1 只保证一个具名主角并按单主角处理（不是提问，是告知）。
   - 交付物：带编号的预览拼图、完整单图、`result.md`（简短结果说明与已知问题，含"该项未经可靠审核"标注）、manifest。`make`/`status` 完成时的 JSON 里给出这些路径。
2. **SKILL.md**（放在 `skill/story-cg-v1/SKILL.md`，目录名监工安装时沿用，不与已有 skill 重名；注意已有 `story-cg-director`，名字不得相同）：
   - 保持简短：何时使用、怎么调用脚本、哪些情况向用户提问、如何展示结果（拼图用 Hermes 的媒体方式展示，附简短说明与已知问题）。
   - 不要把流程写成长篇自然语言规则让运行时模型逐条执行；流程在脚本里。
   - 写清长任务的用法：`make` 后轮询 `status`，而不是阻塞等待。
3. **skill 目录内的脚本**：`skill/story-cg-v1/scripts/storycg`（或 .sh），调用工作目录的项目环境（项目路径由安装脚本写入，不硬编码在 SKILL.md 里）。
4. **安装脚本** `tools/install_hermes_skill.sh`（监工执行）：把 `skill/story-cg-v1/` 复制到 `~/.hermes/skills/story-cg-v1/`，写入项目路径；目标已存在时拒绝覆盖（除非 `--force`，并提示）；不改 Hermes 全局配置；打印安装后的 `hermes skills list` 相关行。
5. 离线测试：`make --storyboard-first` 的 JSON 形状、需要提问时的 JSON、多具名角色时的告知、status/deliver 的 JSON、安装脚本在临时 HOME 下的行为（不要碰真实 `~/.hermes`）。
