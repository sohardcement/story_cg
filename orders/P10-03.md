# 工单 P10-03：重复主角判定改为由子项推导，加候选去重；冻结后用新样本外部验证（不出图）

先读 AGENTS.md（含补充禁令）、PROGRESS.md 的决策 D21、D23 和"审核器 v3 校准结果"一节、`reports/P10-02.md`，以及监工真值 `verify/P10-03-labels.json`（只读）。本工单**出图 0**。

## 背景（监工对 P10-02 的诊断）

1. **判定词在两层里意思相反。** v3 的 extra_protagonist 让模型对每个候选给出 hair_color / hairstyle / eye_color 三个子项（ok 表示"和身份一致"），再给一个候选整体 status（ok 表示"不是重复"）。S1–S3、S5 中，模型三个子项都判"一致"，理由里也写了"是主角的另一个形象"，但整体 status 填了 ok。冻结映射只读整体 status，结果检出只有 20%。用 P10-02 已有的原始响应，按子项事后推导：S 集 10/10 检出、0/14 误报。这只是开发集上的观察，不能当作校准结果。
2. **同一个人被重复检测。** `review_v3.extra_candidates` 在包含主脸的人物框里取最小的作主体，其余**同样包含主脸**的框会被当成候选，而它们其实就是主角本人。改成按子项推导后，这类候选会被判成重复，造成误报。
3. **检测下限。** 有些画得很小、风格化的重复主角，本机检测器在任何设置下都给不出候选：阈值降到 0.15、imgsz 1280、2×2 切块，监工都试过。本工单不处理这一层，只要求如实统计。

## 要做的

1. **映射**：每个候选的结论由子项确定性推导，模型给的候选整体 status 只记录、不参与判定。
   - duplicate：hair_color = ok **且** hairstyle = ok **且** eye_color ≠ mismatch，**并且**不属于"分镜声明了 reflection 且模型判 is_reflection"的情况。
   - not_visible：没有判 mismatch 的子项，但 hair_color 或 hairstyle 为 not_visible。
   - 其余为 ok。
   - 整张图：任一候选为 duplicate → duplicate；否则沿用 P10-02 的汇总方式。
   - 规则写成通用代码，不得出现任何样本、角色或作品名。
2. **候选去重**：在 `extra_candidates` 里排除两类人物框：包含主脸的框（主体那个之外的全部），以及与主体人物框 IoU ≥ 0.5 的框。脸候选的规则不变。检测阈值、裁切参数、提示词全部不变。
3. **离线测试**（先红后绿）：覆盖整体状态与子项冲突、声明倒影、发色或发型 mismatch、瞳色 mismatch、not_visible、两类自我重叠框被排除、真正的小号候选保留。
4. **开发集复算（0 次调用）**：用 P10-02 的 S1–S12 原始响应，按新映射重新计算；新过滤会去掉的候选就从原响应里剔除。单独列为"开发集"，不参与状态判定。
5. **冻结 v3.1**：把审核器代码、提示词、阈值和执行脚本的哈希写入 `calibration/v3.1/reviewer_freeze.json`。冻结必须在跑外部验证之前完成，之后本工单内不再改审核器。
6. **外部验证**：`verify/P10-03-labels.json` 的 11 个样本，每个跑 2 次。输入用样本记录里的 `job`（identity.json、storyboard 对应 shot_number 的条目）和 `portrait`。直接调用冻结的 `review_v3.prepare` / `review_v3.audit`。检测器给不出候选的样本，如果代码路径不需要视觉调用就能得出 extra_protagonist，就不要发请求；如果需要，就照常调用。
7. **统计口径**（开跑前定死，不许事后改）：
   - **候选层**（labels 里 `level=candidate`，即 H1–H4、K1–K3）用来判定可靠性状态，门槛不变：检出 ≥ 75%，误报 ≤ 20%，error/ok 各 ≥ 3 个不同样本。
   - **系统层**（全部 11 个样本）必须一起报告。
8. **发布**：`config/review_reliability.json` 只更新 extra_protagonist 一项，状态按候选层结果定；加一条说明，写明系统层检出率，以及"检测器看不到的小号人物仍会漏"。v3 原配置保留副本到 `calibration/v3.1/review_reliability_v3.json`。确认交付说明（result.md / review.md）能显示这条说明，没有显示的地方用通用方式补上。

## 不许做

- 改真值、改门槛、改提示词或检测阈值；冻结后改审核器；看过外部验证结果之后改规则再重跑。
- 在代码或提示词里写任何样本、角色或作品专有词；针对 H/K 样本写特例。
- 出图；写 `verify/`、`~/.hermes`；git commit；改 TASK.md、SUPERVISOR.md、PROGRESS.md、orders/、AGENTS.md。
