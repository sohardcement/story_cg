# 工单 V2-50：远景小脸的面部精修（D87）

用户决定（D87，2026-10-12）："优化动作后优化再出面部精修吧"。动作已由 V2-49 完成。监工的面部精修实验（PROGRESS D87 "面部精修实验"，`verify/v2/face-ab/`，脚本 `run_face.py`、`repaste.py`）结论：
- 远景镜的脸长边只有 38–114 像素，眼睛常常糊掉、没画出来；中景是 170–292 像素，不需要精修。
- 以脸为中心裁正方形（边长取脸长边的 3 倍），放大到 1024，用这张候选自己的工作流做图生图（denoise 0.5，构图 tag 换成 closeup 档），缩回原尺寸后只贴脸周围的椭圆。14 张里 13 张明显变好，身份没走样，看不出接缝。
- 按正方形整块贴回会把背景重画（多出窗帘竖纹、细树），到方框边上就断了。所以必须用椭圆遮罩。

本工单把这个做法原样接进流水线，参数和实验一致。

## 背景（监工已核实，以 7006ece 为准）

- 候选在 `candidates._run_round` 里逐个生成：`runner.run_candidate` 出图，然后从 `state['attempts']` 取出这张候选的 attempt，`audit_candidate` 审核它的 `attempt['image']`，结果存进 `candidates.json` 的 record（`record['image']` 取自 `attempt['image']`）。
- 交付用 `cycle.selected_attempt`，按 `shot_id == 'shotNN'` 和 `attempt_number` 找 attempt，取 `attempt['image']`。拼图、`manifest.json`、`result.md` 都从这里来。
- `runner._process` 负责提交、等待、下载和续跑对账；`runner._new_attempt` 检查 `max_images_per_job` 和提交数；`budget.Budget.check(images=1)` 检查整个任务的出图额度和时间。
- 读 `state['attempts']` 的地方都按 `shot_id` 精确匹配（`cycle.py:39`、`agent.py:307`、`pipeline.py:108/171`），`state.make_prefix` 允许 shot_id 带下划线。
- `assembly.assemble_prompt`：构图 tag 是 `framing_rule(config, shot['framing'])['tags']` 加 `config['camera_tags'][shot['camera_angle']]`，后面接动作类 tag（`shot['tags']`、陪衬 tag、`reflection`）。closeup 档的构图 tag 是 `upper_body, close-up`。
- 节点 4 的正向文字是 `f'{positive_prefix}, {positive_tags}'`；`build_workflow` 的空 latent 是节点 `"6"`（`EmptyLatentImage`），VAE 在 `["1", 2]`。
- `controls.upload_reference(root, path, client)` 按 sha256 去重上传，记在 `reference_uploads.json`。
- `storycg.detect.detect_faces(image)` 返回 `[{'bbox': [x0, y0, x1, y1], 'confidence': …}, …]`，模型在 `models/detect/`（.v2 里是指向主线的链接）。
- `tools/v2_43_capture.py` 的假 ComfyUI 返回纯色图，检测不到脸。

## 要做

1. **配置**：`config/default.json` 新增一节，值照抄：
   ```json
   "face_refine": {"max_face_px": 140, "crop_scale": 3.0, "side": 1024, "denoise": 0.5, "mask_scale": 1.8, "feather": 0.15}
   ```
   任务的 config 里没有这一节时（旧任务续跑），不精修，行为和现在完全一样。不加开关。
2. **新模块 `src/storycg/face_refine.py`**，几何和实验逐字一致：
   - 取脸：`detect_faces` 结果里置信度最高的一张。没有脸 → 状态 `no_face`。脸长边 `max(x1-x0, y1-y0)` ≥ `max_face_px` → 状态 `not_needed`。
   - 裁剪框（照抄 `verify/v2/face-ab/run_face.py` 的 `crop_box`）：`cx, cy` 为脸框中心，`side = min(max(w, h) * crop_scale, 图宽, 图高)`，`left = min(max(0, cx - side/2), 图宽 - side)`，`top` 同理，四个值各自 `int(round(v))`。
   - 裁剪图用 LANCZOS 缩放到 `side`×`side`（1024），存进任务目录，用 `upload_reference` 上传。
   - 精修工作流：拷贝这张候选的 `attempt['workflow']`，只改这几处：节点 4 的文字换成精修提示词；删掉 `EmptyLatentImage` 节点；新增 `LoadImage`（上传的裁剪图）→ `VAEEncode`（vae 取 `CheckpointLoaderSimple` 的输出 2）接到 KSampler 的 `latent_image`；KSampler 的 `denoise` 设为配置值；`SaveImage` 换成精修 attempt 自己的前缀。seed、负向、IPAdapter、定妆图、采样参数都不动。
   - 精修提示词：`assemble_prompt` 多返回一个键 `closeup_positive_tags`，和 `positive_tags` 的区别只有构图那段：换成 closeup 档的构图 tag，不加机位 tag，后面接的动作类 tag 和原来一模一样（同一份列表；如果其中有 tag 和 closeup 构图 tag 相同，就去掉）。节点 4 的文字是 `f'{positive_prefix}, {closeup_positive_tags}'`。`assemble_prompt` 原有的返回值一个字不变。
   - 贴回（照抄 `verify/v2/face-ab/repaste.py` 的 `tight_paste`）：精修结果用 LANCZOS 缩回裁剪框边长；以脸框中心（换算到裁剪框内坐标）为圆心，半径 `rx = 脸宽 * mask_scale / 2`、`ry = 脸高 * mask_scale / 2`；`blur = max(脸宽, 脸高) * feather`；在全黑的 L 图上画实心椭圆 `(cx - rx + blur, cy - ry + blur, cx + rx - blur, cy + ry - blur)`，再 `GaussianBlur(blur)`，用它作遮罩贴回原图。存为 PNG。
3. **提交走 runner**：精修是一次独立的 ComfyUI 提交，记进 `state['attempts']`，`shot_id` 为 `shotNN_face`，`candidate` 为 `None`，另记它精修的是哪张候选（shot_id、attempt_number、candidate）。提交、等待、下载、续跑对账都用 `_process`，改 state 时持有 `_job_lock`。它计入 `max_images_per_job` 和提交数。
4. **接入 `_run_round`**：候选出图完成（`status == 'completed'`）后、审核之前做精修。
   - 精修成功：合成图替换这张候选 attempt 的 `image`（path、sha256、宽高）；原来的 `image` 和精修信息（状态、脸框、脸长边、裁剪框、denoise、精修 attempt 的 shot_id 和 attempt_number）记在这张候选 attempt 的 `face_refine` 里。之后的筛选、审核、并排挑选、终审、拼图、候选总图、交付、用户手动 `pick` 用的都是合成图，这些代码不改。
   - 没精修（`no_face`、`not_needed`）：只在 attempt 上记 `face_refine` 的状态和脸长边，图不动。
   - 额度不够（`Budget.check(images=1)` 抛 `BudgetExceeded`，或 runner 的额度检查不让提交）：不精修，状态 `skipped_budget`，用原图继续，任务不失败。
   - 精修提交失败或没拿到图：状态 `failed`，用原图继续，任务不失败。
   - 续跑幂等：已经有 `face_refine` 结论的候选不再精修；精修 attempt 提交了但没下载完，走 `_process` 的续跑对账，不重复提交；下载完但合成图没写，补写合成图。
   - `candidates.json` 的 record 和 `manifest.json` 的 `candidates` 记录各带一份 `face_refine` 摘要（状态、脸长边）。
5. **result.md**：
   - 概况里的出图行改成 `本组出图：N 张（镜头候选 X 张，面部精修 Y 张，定妆图 Z 张）`，Y 是完成的精修 attempt 数。没有精修时这一行和现在一字不差。
   - 每镜：选中的候选做过精修时，加一行 `- 面部精修：脸长边 {n} 像素，已精修；原图 {原图文件名}`；状态是 `skipped_budget` 或 `failed` 时，加一行 `- 面部精修：脸长边 {n} 像素，没有精修（{原因}）`，原因分别写 `出图额度不够`、`精修出图失败`。`not_needed`、`no_face` 不写。
