## 二、第一批删减（TASK-v2 §4）

| 删什么 | 位置 |
|---|---|
| 瞳色颜色采样 | `eye_sampling.py` 及 `detection_review.py` 里调用它的分支 |
| 重复的修复循环 | `cycle.py` 里只有测试在调用的 `run_repair_cycle`、`apply_round`、`diagnose`、`detection_improved` |
| 只有测试调用的旧路径 | `tiers.py` 的 `determine_l1`、`prepare_l2`、`build_l2_workflow`；`repairs.py` 的 `rewrite_composition`、`composite_region`；`detect.py` 的 `crop_face` |
| 区域重绘修复原语 | `repairs.py` 的 region 系列 |

要求：

- **删之前逐个确认**：从正式入口（`python -m storycg` 的全部子命令，以及 Hermes 用的 `make / status / approve / resume / deliver`）确实走不到。可以参考 `audit/functions.tsv` 和 `audit/callgraph.md`，但以你现在的静态检查为准。
  - 发现某一项其实走得到，就**不删**，在报告里说明。
- 只为被删函数服务的测试一起删掉；其他测试不得改弱，包括放宽断言或改成 skip。
- 删完后：
  - 全量测试通过；
  - `python -m storycg --help` 和各子命令的 `--help` 正常；
  - 用一个已有任务目录跑一次离线的 `status` 和 `deliver`，确认交付物能照常生成。只读的话，可以先把任务目录复制到工作树里再跑。
